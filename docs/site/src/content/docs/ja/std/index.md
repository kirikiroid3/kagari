『標準ライブラリのリファレンス』では、Kagari の標準ライブラリ `std` を説明します。ライブラリの公開アイテムをすべて、正確なシグネチャと意味とともに載せています。構成は Node.js の API ドキュメントにならい、モジュールごとに 1 ページです。

言語そのもの（構文、関数種別、シーン、組み込み構文、数値）は [言語リファレンス](../reference/index.md) で説明しています。このリファレンスは、その内容を理解していることを前提とします。

## ページの構成 {#page-structure}

モジュールのページは、どれも同じ形式で書かれています。

1. タイトルはモジュールのパスです（例：`` `std::time` ``）。
2. **安定性** の行（`> **安定性:** 安定 — …`）で、モジュールの概要と安定性を示します（後述）。
3. 導入の段落で、モジュールの用途と、アイテムがどの関数種別かを説明します。
4. 必要に応じて **概要** の表を置き、ページ内のアイテムを一覧にします。
5. アイテムごとに H2 の節を設け、モジュールのソースファイルでの宣言順に並べます。見出しにはアイテムの種類を付けます。英語版の `Struct:`、`Enum:`、`Trait:`、`Type:`、`Constant:`、`Function:` に当たり、日本語版では「構造体：」「列挙型：」「トレイト：」「型：」「定数：」「関数：」と書きます。
6. メソッド、関連関数、バリアントのまとまりは、型の節の下に H3 の節を 1 つずつ設けます。

各アイテムの節は、`std` での宣言そのままのコードから始まり、続けて次の内容を載せます。

- 引数ごとの項目：名前、型、意味
- `Returns:`（日本語版では「戻り値：」）：戻り値の型と意味
- バッジ行：`Kind: … · Builtin: … · Profile: …`（日本語版では「種別：… · 組み込み：… · プロファイル：…」。後述）
- 意味、境界的な場合の動作、関連する診断、短い例

手引き（*演出の実例*、*ゲームシステムの実例*）では、アイテムの組み合わせ方を紹介します。付録には、std のアイテムに適用されるコンパイラの規則と、ランタイムプロファイルごとの対応範囲をまとめています。

## 安定性 {#stability-index}

|安定性|意味|
|---|---|
|**安定**（Stable）|コンパイラとランタイムに実装済みです。シグネチャと意味が変わるのは、その旨を明記した新しいバージョンのツールチェインが出たときだけです。|
|**暫定**（Tentative）|実装済みですが、設計はまだ固まっていません。名前、シグネチャ、意味が変わることがあります。|
|**予定**（Planned）|設計済み、または要望の段階で、未実装です。ページには意図を書いていますが、まだ何も使えません。|

モジュールの安定性は、ページの最初の行に書きます。モジュールと安定性が異なるアイテムには、個別に `安定性:` の注記を付けます。

## 種別のバッジ {#kind-badges}

アイテムのバッジ行には、そのアイテムの関数種別を書きます。

|バッジ|意味|
|---|---|
|`Kind: const fn`|純粋な関数。どの種別のコードからも呼べます。物語の中では、定数を引数にした呼び出しは畳み込まれ、有限型の実行時の値を引数にした呼び出しは表化されます。|
|`Kind: fn`|普通のコード。ゲームシステム、UI、設定に使います。`const fn` や物語からは呼べません。|
|`Kind: pushdown fn`|物語のコード。物語からしか呼べず、中にはシーンからしか呼べないものもあります。|

種別どうしの呼び出し規則は、言語の規則そのままです（[関数種別](../reference/concepts/kinds.md) を参照）。std のメソッドや組み込みのアイテムにも、自分で書いた関数とまったく同じように適用されます。

## `#[builtin]` アイテム {#builtin-items}

`#[builtin]` を付けたアイテムは `std` の中に本体がなく、コンパイラかエンジンが提供します。

- `#[builtin]` の**型**は中身が見えません。外から見えるフィールドはなく、レイアウトを前提にすることもできません。使うときは、メソッドかその型を受け取る関数を通します。`Text`、`Screen`、`Narrative`、アセット型などがこれに当たります。
- `#[builtin]` の**関数**は、ほかの関数と同じく、宣言どおりのシグネチャと種別を持ちます。
- `#[builtin]` は `std` 専用です。ゲーム側で組み込みのアイテムを宣言することはできません。

`#[builtin]` が付いていないものは、すべて普通の Kagari のコードで、制作者が自分で書くこともできたものです。`std::time` やテキスト効果のコンストラクターがその例です。

バッジには `Builtin: yes` か `Builtin: no` と書きます（日本語版では「組み込み：はい」「組み込み：いいえ」）。

## シグネチャの表記 {#signature-conventions}

- シグネチャは `std` のソースから写したものです。ドキュメントコメントは短くするか省いています。
- メソッドの見出しは `` `Type::method(args)` `` の形で、`self`、`&self`、`&mut self` は宣言どおりに書きます。
- ジェネリクスの型引数は Rust と同じく `<T>`、`<T: Eq>`、`<const N: usize>` と書きます。
- `Int<lo, hi>` は言語の範囲付き整数型です。Rust の整数（`u8` … `i128`、`usize`、`isize`）と `bool` は言語の型で、std のアイテムではありません。
- 位置と長さの単位はピクセル、時間は `Duration`、割合は `Decimal` で表します。
- 「評価エラー」とは、呼び出しが定数評価される場合はコンパイルエラー、そうでなければ実行時エラーのことです。

## プロファイルの注記 {#profile-notes}

ランタイムプロファイルとは、ランタイムが提供する機能とアセット形式をまとめたものです。あるプロファイルで使えないアイテムには、バッジ行にその旨を書きます（例：`Profile: not in native_v0`）。対応状況の一覧は [ランタイムプロファイル](./appendix/profiles.md) にあります。
