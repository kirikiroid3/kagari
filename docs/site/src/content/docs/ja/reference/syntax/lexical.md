---
title: "字句構造"
---

ソースファイルは**トークン**（識別子、キーワード、リテラル、ラベル、記号）の並びに分割されます。空白とコメントはトークンを区切る役目しか持ちません。`.kis` と `.kix` の字句解析器は共通で、`.kix` ファイルの[組み込み構文](./forms.md)も同じトークンから組み立てます。

## ソーステキスト {#source-text}

- ソースファイルの文字コードは UTF-8 です。UTF-8 として不正なファイルは読み込めず、読み込めなかったモジュールは「見つからないモジュール」として報告されます（[`E1002`](../../diagnostics/modules.md#e1002)）。
- バイトオーダーマーク（U+FEFF）は使えません。書くと予期しない文字として扱います。
- 改行は LF と CRLF のどちらでもかまいません。どちらも空白として扱います。

## 空白 {#whitespace}

空白として扱う文字は、スペース（U+0020）、タブ（U+0009）、ラインフィード（U+000A）、垂直タブ（U+000B）、フォームフィード（U+000C）、キャリッジリターン（U+000D）、ネクストライン（U+0085）、左から右へのマーク（U+200E）、右から左へのマーク（U+200F）、行区切り（U+2028）、段落区切り（U+2029）です。これは Unicode の `Pattern_White_Space` そのもので、Rust の空白とも一致します。全角スペース（U+3000）など、これ以外の Unicode の空白文字は空白とみなさず、文字列リテラルの外に書くとエラーになります。

## コメント {#comments}

| 形 | 意味 |
| -- | ---- |
| `// …` | 行コメント。行末まで続く |
| `/* … */` | ブロックコメント。入れ子にでき、`/* a /* b */ c */` 全体で 1 つのコメントになる |
| `/// …` | 直後のアイテムに付けるドキュメントコメント。エディタのホバーに表示される |
| `//! …` | 慣習として、ファイル先頭に書いてモジュールを説明する |

コメントはどのトークンの間にも置けます。組み込み構文の中でも同様です。ドキュメントコメントは、スラッシュがちょうど 3 つで始まる行コメントです（`////` は普通のコメント）。`//!` と `/** … */` は、ツールから見て特別な意味はありません。`*/` で閉じていないブロックコメントはエラーです。

```kis
//! The characters of the game.

/// Hanako's entity on the screen.
pub const HANAKO: EntityId = EntityId(216); /* ids below 1000 are reserved /* by us */ */
```

## 識別子 {#identifiers}

識別子は、Unicode の `XID_Start` に属する文字か `_` で始まり、その後に `XID_Continue` に属する文字が 0 個以上続きます。ASCII 以外の文字も使えます。

```kis
const 花子: EntityId = EntityId(216);
```

- `_` 単独は識別子になりません。パターンではワイルドカード、型ではプレースホルダを表します。
- [厳格キーワード](#strict-keywords)は識別子に使えません。生識別子（`r#match`）もありません。
- 識別子は書かれたとおりに比較します。コンパイラは Unicode の正規化を行いません。

## キーワード {#keywords}

### 厳格キーワード {#strict-keywords}

次の語は常にキーワードで、名前には使えません。

```text
as        break     const     continue  crate     else      enum      false
fn        for       if        impl      in        let       loop      match
mod       mut       pub       return    self      Self      static    struct
super     trait     true      type      use       while
```

このうち次の 2 つは、使える場面が限られています。

- `as` はインポートの別名（`use a::b as c;`）に使います。キャスト演算子としても構文解析はしますが、必ずエラーになります（[`E2019`](../../diagnostics/types.md#e2019)）。詳しくは[変換](./numbers.md#conversions)を参照してください。
- `trait` はトレイトの宣言に使いますが、トレイトを宣言できるのは標準ライブラリだけです（[`E1012`](../../diagnostics/modules.md#e1012)）。

### 文脈キーワード {#contextual-keywords}

次の語は特定の位置でだけキーワードとして働き、それ以外の位置では普通の識別子です。

| 語 | キーワードになる位置 | 例 |
| -- | -------------------- | -- |
| `pushdown` | `fn`（関数または関数ポインタ型）の直前、または `Fn(` の直前 | `pushdown fn visit()`、`pushdown Fn(Map)` |
| `scene` | 型の中の `fn` の直前 | `scene fn() -> Answer` |
| `Fn` | 型の中の `(` の直前 | `Fn(u32) -> bool` |

### Kagari ではキーワードでない Rust のキーワード {#rust-keywords-that-are-not-keywords}

`async`、`await`、`dyn`、`extern`、`move`、`ref`、`unsafe`、`where`、`yield` や、Rust の予約語（`abstract`、`box`、`macro` など）は、Kagari では普通の識別子です。対応する機能もありません。[Rust との違い](./rust-differences.md)を参照してください。

## リテラル {#literals}

| リテラル | 例 | 型 |
| -------- | -- | -- |
| 整数 | `0`、`1_000`、`0xFF`、`0o17`、`0b1010`、`5u8`、`0x1Fi64` | 整数型。[整数リテラル](./numbers.md#integer-literals)を参照 |
| 十進数 | `0.5`、`1.0`、`12.25`、`1_000.000_1` | `Decimal` |
| 文字列 | `"Mio"`、`"line\nbreak"`、`"\u{3042}"` | `Text` |
| 真偽値 | `true`、`false` | `bool` |

文字リテラル、バイトリテラル、バイト文字列、生文字列、浮動小数点数リテラルはありません。

### 整数リテラル {#integer-literals}

整数リテラルは次の 3 つの部分からなります。

1. 省略可能な基数接頭辞：`0x`（16 進）、`0o`（8 進）、`0b`（2 進）。小文字で書きます。
2. その基数の数字。1 桁以上必要で、区切りの `_` はどこに置いてもかまいません。
3. 型を固定する省略可能な接尾辞：`u8`、`u16`、`u32`、`u64`、`u128`、`usize`、`i8`、`i16`、`i32`、`i64`、`i128`、`isize` のいずれか。

16 進リテラルでは、16 進数字でも `_` でもない最初の文字から先を接尾辞とみなします。それ以外の基数では、10 進数字でも `_` でもない最初の文字から先が接尾辞です。数字がない場合、基数の範囲外の数字がある場合（`0b102`）、接尾辞が上記以外の場合はエラーになります。値は 128 ビットに収まる必要があります。

接尾辞は最長一致で読むため、`1e5` は整数 `1` に不正な接尾辞 `e5` が付いたもの、`0X1F` は `0` に不正な接尾辞 `X1F` が付いたものになります。マイナス記号はリテラルに含まれません。`-128i8` は `128i8` に演算子 `-` を適用した式で、符号を反転した値が型に収まるため、コンパイラは受け付けます。

### 十進数リテラル {#decimal-literals}

十進数リテラルは、数字、`.`、数字の順に並べたものです。どちらの数字部分も、最初の数字の後には区切りの `_` を置けます。`.` の両側に数字が必要で、`1.` や `.5` は十進数リテラルになりません。指数表記も接尾辞もありません。型は [`Decimal`](./numbers.md#decimal) です。

次の 2 つは十進数リテラルに見えますが、違います。

- `.` の直後の数は、タプルのインデックスとして分けて読みます。`pair.0.1` は、`pair` のフィールド `0` の、さらにフィールド `1` です。
- `..` の直後の数は分けません。`0..1.5` は `1.5` までの範囲です。

### 文字列リテラル {#string-literals}

文字列リテラルは、テキストを二重引用符で囲んだものです。複数行にまたがってもよく、途中の改行も値に含まれます。バックスラッシュはエスケープの始まりです。

| エスケープ | 文字 |
| ---------- | ---- |
| `\n` | ラインフィード |
| `\r` | キャリッジリターン |
| `\t` | タブ |
| `\\` | バックスラッシュ |
| `\"` | 二重引用符 |
| `\0` | U+0000 |
| `\u{…}` | 1〜6 桁の 16 進数で表した Unicode スカラー値。桁の間に区切りの `_` を置ける |

これ以外のエスケープ（`\'` や `\x41` など）はエラーです。Unicode スカラー値にならない `\u{…}`（サロゲートや U+10FFFF を超える値）もエラーになります。行末にバックスラッシュを置いて行を継続する機能はありません。閉じ引用符のない文字列もエラーです。

文字列リテラルの型は、プログラム中の定数テキストを表す `Text` です（[Text と String](./types.md#text-and-string) を参照）。

```kis
const GREETING: Text = "\"Good morning,\" she said.\n\u{2026}";
```

### 真偽値リテラル {#boolean-literals}

`true` と `false` はキーワードで、`bool` 型の 2 つの値を表します。

## ラベル {#labels}

**ラベル**は `'` の直後に識別子を続けたもので、`'outer` のように書きます。ループに名前を付け、`break` や `continue` の行き先を示すのに使います（[制御フローとループ](./control-flow.md)を参照）。Kagari にはライフタイムがないため、`'` の用途はこれだけです。

```kis
'outer: for row in 0..3 {
    for col in 0..3 {
        if col == row { continue 'outer; }
    }
}
```

## 記号 {#punctuation}

字句解析器は記号を 1 文字ずつのトークンにします。文法上もっと長い演算子が必要な位置では、構文解析器が**隣接した**（間に何も挟まない）文字をつなげて読みます。そのため、`Vec<Vec<u8>>` の `>>` は 2 つのジェネリクス引数リストを閉じ、`a >> 2` はシフトになります。空白を挟んだ `- >` は `->` になりません。

| トークン | 用途 |
| -------- | ---- |
| `(` `)` | グループ化、タプル、呼び出し、引数リスト、タプル構造体 |
| `[` `]` | 配列、インデックス、配列型、属性、`t![…]` |
| `{` `}` | ブロック、構造体リテラル、アイテムリスト、`use` のグループ、`t![…]` の `{expr}` |
| `<` `>` | ジェネリクス、小なり、大なり |
| `,` `;` `:` | 区切り。`:` は型や境界の前に置く |
| `.` | フィールドアクセス、メソッド呼び出し、タプルのインデックス |
| `=` | 代入、初期化子、組み込み構文の属性（`who = …`） |
| `!` | 論理否定とビット否定、組み込み構文（`s!(…)`）、テキスト効果（`!["…"](…)`） |
| `+` `-` `*` `/` `%` | 算術。ほかに `-` は符号反転、`*` は参照外しとグロブインポート、`+` は境界の連結 |
| `&` | 参照（`&x`、`&mut x`、`&T`）、ビット積 |
| `\|` | クロージャ（`\|x\| x + 1`）、ビット和、パターンの選択肢、ルビの読み |
| `^` | ビット排他的論理和 |
| `#` | 属性（`#[scene]`） |
| `?` | `Option` と `Result` に対する `?` 演算子 |
| `::` | パスの区切り、ターボフィッシュ（`f::<u8>()`） |
| `->` | 戻り値型 |
| `=>` | match のアーム、選択肢のアーム |
| `==` `!=` `<=` `>=` | 比較 |
| `&&` `\|\|` | 論理積、論理和 |
| `<<` `>>` | シフト |
| `+=` `-=` `*=` `/=` `%=` `^=` `&=` `\|=` `<<=` `>>=` | 複合代入 |
| `..` `..=` | 範囲、残余パターン |

次の文字はトークンにならず、コメントと文字列の外に書くとエラーです：`@`、`$`、`~`、`` ` ``、`\`、ラベルを始めない `'`。`...` もトークンではありません。

## `.kix` ファイルの組み込み構文 {#forms-in-kix-files}

`.kix` ファイル専用のトークンはありません。**組み込み構文**は、識別子、`!`、開き括弧（`(`、`[`、`{`）で始まります。`s!(…)`、`t![…]`、`choice!{…}`、`button!{…}` がその例です。`t![…]` の中には、文字列リテラル、ルビ `["漢字"]("かん" | "じ")`、テキスト効果 `!["…"](effect)`、埋め込み `{expr}` をカンマで区切らずに並べます。`.kis` ファイルに組み込み構文を書くとエラーです。各構文の詳細は[組み込み構文](./forms.md)で説明します。

## 字句エラー {#lexical-errors}

字句エラーはすべて [`E0001`](../../diagnostics/syntax.md#e0001) として報告されます。予期しない文字、閉じていないブロックコメントや文字列、未知のエスケープ、不正な `\u{…}`、不正な整数リテラルがこれに当たります。エラーの後もファイルの最後まで読み進めるため、後続のエラーもあわせて報告されることがあります。
