*暫定。* この章ではメモリモデルを定めます。Rust よりあえて単純にしてあり、ライフタイム、借用チェッカー、ムーブはありません。

## 値セマンティクス {#value-semantics}

型はすべて値型です。代入、引数渡し、戻り値のどれでも値はコピーされ、コピーを変更しても元の値は変わりません。実装が記憶領域を共有し、書き込み時にコピーする方式をとってもかまいませんが、プログラムからその違いは見えません。

```kis
struct Point { x: i32, y: i32 }

fn demo() -> i32 {
    let a = Point { x: 1, y: 2 };
    let mut b = a;      // a copy
    b.x = 10;
    a.x                 // still 1: `a` is unchanged and still usable
}
```

ムーブもデストラクタもありません。値は、どこからも保持されなくなった時点で消えます。

## 場所と可変性 {#places-and-mutability}

**場所**とは値を保持するもののことです。ローカル変数、パラメータ、物語変数、それらのフィールドや要素、参照の指す先（`*r`）が該当します。代入、複合代入、`&mut`、`&mut self` をレシーバーにとるメソッドの呼び出しには、**可変**な場所が必要です。可変な場所は次のとおりです。

- `let mut` のローカル変数、または `mut` パラメータ
- `pushdown fn` のコードの中の物語変数（`static mut`）
- 可変な場所のフィールドや要素
- `&mut` を経由してたどった場所

`&T` を経由してたどった場所、`mut` の付いていないローカル変数やパラメータ、定数、ハンドルは読み取り専用です。これらを変更するとエラー [`E3017`](../../diagnostics/kinds.md#e3017) になります。

## 参照 {#references}

`&T` と `&mut T` を使うと、値をコピーせずに読み書きできます。`&x` と `&mut x` で場所 `x` への参照を作り、`*r` で参照の指す場所を表します。フィールドアクセスとメソッド呼び出しでは、参照を自動でたどります。

```kis
fn bump(counter: &mut u32) {
    *counter += 1;
}

fn demo() -> u32 {
    let mut n: u32 = 0;
    bump(&mut n);
    let r = &mut n;
    let s = r;          // copies the pointer, not the value
    *s += 1;
    n                   // 2
}
```

参照は、場所を指す共有ポインタです。参照があるかぎり指す先の場所は生き続け、参照をコピーしてもコピーされるのはポインタで、値ではありません。

- `fn` と `const fn` のコードでは、参照は普通の値です。ローカル変数への束縛、フィールドやコレクションへの格納、戻り値としての返却、クロージャでのキャプチャができます。
- ある参照を通して書き込むと、同じ場所を指す他の参照すべてから変更が見えます。借用チェッカーはないので、同じ場所への `&mut` が同時に 2 つあってもかまいません。ゲームは VM 上で動くため、思わぬ動作になることはあっても、メモリが壊れることはありません。
- `&mut T` は暗黙に `&T` に変換されます。
- 参照どうしの `==` は、指す先の値を比較します。
- `const` アイテム、物語変数、ハンドルの型には参照を含められません（[`E3012`](../../diagnostics/kinds.md#e3012)）。

典型的な使い方はレンダー関数に見られます。画面を値として受け取り、`&mut self` をとるメソッドで変更してから返します。

```kis
const HANAKO: EntityId = EntityId(216);

const fn hanako_appears(mut screen: Screen) -> Screen {
    screen.entity(HANAKO).opacity().change(1.0).apply_animation(tween(ms(300)));
    screen
}
```

### 物語の中の参照 {#references-in-the-story}

`pushdown fn` の中では、参照は**第二級**の値です。呼び出し先へ渡すことはできても、保持することはできません。

- 参照型を使えるのはパラメータの型だけです。メソッドのレシーバー（`&self`、`&mut self`）もこれに含みます。ローカル変数、フィールド、キャプチャした変数に参照は保持できません（[`E3014`](../../diagnostics/kinds.md#e3014)）。
- 関数が参照を返せるのは、レシーバーが参照の場合だけです。返った参照は、それを作った文の終わりまでしか使えません（[`E3014`](../../diagnostics/kinds.md#e3014)）。
- **排他性。** 1 回の呼び出しの中で、`&mut` として渡した場所を別の引数にも渡すことはできません。これにより、一方から変更されうる 2 つのパラメータが別名になることはありません（[`E3016`](../../diagnostics/kinds.md#e3016)）。

```kis
static mut TRUST: Int<0, 5> = 0;
static mut DOUBT: Int<0, 5> = 0;

pushdown fn shift(from: &mut Int<0, 5>, to: &mut Int<0, 5>) {
    *from -= 1;
    *to += 1;
}

pushdown fn reassure() {
    shift(&mut DOUBT, &mut TRUST);    // fine
    shift(&mut TRUST, &mut TRUST);    // E3016: the same place twice
}
```

参照は渡された呼び出しより長く生きず、他の引数と別名になることもありません。そのため、`&mut x` をとる `pushdown fn` は、`x` のコピーを受け取り、戻るときに呼び出し側が結果を書き戻すのとまったく同じ動作になります。`pushdown fn` の `&mut` 引数は有限型の入出力パラメータにすぎず、物語の状態がポインタを保持することはありません。だからこそ、参照があっても[物語の解析](../concepts/kinds.md#why-this-works)に支障はありません。

## クロージャ {#closures}

```kis
fn scaled(values: [i32; 3], factor: i32) -> [i32; 3] {
    let scale = |v: i32| v * factor;                            // captures a copy of `factor`
    let clamp = |v: i32| -> i32 { if v > 100 { 100 } else { v } };
    [clamp(scale(values[0])), clamp(scale(values[1])), clamp(scale(values[2]))]
}
```

クロージャは `|parameters| body` と書きます。文脈から型がわかる場合は、パラメータの型を省略できます。戻り値型 `-> R` を明示するときは、本体をブロックにする必要があります。`move` はありません。

クロージャは**値でキャプチャ**します。作られた時点で、使っているローカル変数をコピーします。クロージャの中でそのコピーを変更しても、元の変数は変わりません。可変な状態を共有したいときは、参照、物語変数、[シグナル](../concepts/system.md)を使います。参照をキャプチャした場合はポインタがコピーされるので、それを通した書き込みは元の場所に反映されます。

クロージャにも関数と同じく[種別](../concepts/kinds.md)があります。渡す先や格納先のクロージャ型に種別があればそれに従い、なければクロージャを書いた関数の種別になります。本体はその種別の規則で検査します。クロージャで何ができるかは、クロージャを作るコードの種別で決まるということです。

| 種別 | クロージャの扱い | できること |
| ---- | ---------------- | ---------- |
| `fn` | 第一級 | 格納、返却、UI の値（ハンドラ）への組み込み |
| `const fn` | 第一級 | 格納、返却 |
| `pushdown fn` | 第二級 | 引数として渡して呼び出すことだけ。格納、返却、他のクロージャによるキャプチャは不可（[`E3015`](../../diagnostics/kinds.md#e3015)） |

物語の中のクロージャは[即時手続き](../concepts/scenes.md#scenes-and-instant-procedures)です。ステップの実行（[`E3002`](../../diagnostics/kinds.md#e3002)）、シーンの呼び出し（[`E3003`](../../diagnostics/kinds.md#e3003)）、`loop` や `while`（[`E3004`](../../diagnostics/kinds.md#e3004)）はいずれも使えません。

```kix
static mut AFFECTION_MIO: Int<0, 5> = 0;

pushdown fn twice(f: pushdown Fn()) {
    f();
    f();
}

#[scene]
pushdown fn Compliment() {
    twice(|| AFFECTION_MIO += 1);
    s!(t!["Mio smiles."]);
}
```

クロージャが `Eq` になることはありません（[`E2017`](../../diagnostics/types.md#e2017)）。

### 物語の中のクロージャが第二級である理由 {#why-closures-in-the-story-are-second-class}

物語の中でクロージャを第一級にすると、物語の状態がクロージャを含み、そのクロージャがさらにクロージャを含む、という入れ子が際限なく生じます。これは高階プッシュダウンシステムです。決定可能ではあるものの、階数が 1 つ上がるごとに解析のコストが指数的に増えます（Ong, *On model-checking trees generated by higher-order recursion schemes*, LICS 2006）。第二級のクロージャは、関数と、呼び出しが戻れば消える有限個のキャプチャ値の組にすぎません。そのため物語は通常のプッシュダウンシステムのままです。

## クロージャ型とポインタ型 {#closure-and-pointer-types}

関数ポインタ型とクロージャ型には、呼び出すコードの[種別](../concepts/kinds.md)が含まれます。

| 型 | 保持するもの |
| -- | ------------ |
| `fn(A) -> R` | 名前付きの `fn` |
| `const fn(A) -> R` | 名前付きの `const fn`、またはタプル構造体やタプルバリアントのコンストラクター |
| `pushdown fn(A) -> R` | 名前付きの即時手続き |
| `scene fn(A) -> R` | 名前付きの[シーン](../concepts/scenes.md#scenes-and-instant-procedures)（構文は*暫定*。`scene` がキーワードになるのはここだけです） |
| `Fn(A) -> R`、`const Fn(A) -> R`、`pushdown Fn(A) -> R` | その種別のクロージャまたは関数（構文は*暫定*） |

種別は完全に一致する必要があります。`const fn` は `fn(A) -> R` 型の値にならず、シーンは `pushdown fn(A) -> R` 型の値になりません。暗黙に行われる変換は次のとおりです。

- 名前付き関数やコンストラクターは、同じ種別の関数ポインタに変換されます。
- 名前付き関数や関数ポインタは、同じ種別のクロージャ型に変換されます。シーンに対応するクロージャ型はありません。
- 何もキャプチャしないクロージャは、同じ種別の関数ポインタに変換されます。レンダー関数をその場で書けるのはこの変換のおかげです（[インラインのレンダー関数](../concepts/presentation.md#inline-renders)を参照）。変数をキャプチャするクロージャは変換できません（[`E2036`](../../diagnostics/types.md#e2036)）。

```kis
const fn double(x: u32) -> u32 { x * 2 }

fn demo() -> Option<u32> {
    let f: const fn(u32) -> u32 = double;
    let wrap: const fn(u32) -> Option<u32> = Some;     // a variant constructor
    let g: const Fn(u32) -> u32 = f;                   // pointer to closure type
    wrap(g(f(1)))
}
```

関数ポインタがとる値は有限集合（プログラム中の名前付き関数）に限られます。そのため、`pushdown fn`、`scene fn`、`const fn` のポインタは[有限型](./types.md#finite-types)であり、物語に保持させることができます。関数ポインタどうしは同一性で比較します。

ポインタやクロージャを通した呼び出しにも、直接の呼び出しと同じ[呼び出し規則](../concepts/kinds.md#call-rules)が適用されます。呼び出し先の種別は型からコンパイラにわかるからです。
