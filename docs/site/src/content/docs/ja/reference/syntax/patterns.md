---
title: "パターン"
---

パターンは値の形を表し、その一部を変数に束縛します。Rust のパターンと同じものですが、使える形は少なくなっています。パターンを書ける場所は次のとおりです。

| 場所 | 反駁不能である必要 |
| ---- | ------------------ |
| `let pat = value;` | あり |
| 関数とクロージャの引数 | あり |
| `for pat in iterable` | あり |
| `match` のアーム | なし |
| `if let pat = value`、`while let pat = value` | なし |

## パターンの形 {#pattern-forms}

| パターン | 例 | 一致するもの |
| -------- | -- | ------------ |
| ワイルドカード | `_` | 何にでも一致し、何も束縛しない |
| 束縛 | `x`、`mut x` | 何にでも一致し、値を `x` に束縛する |
| リテラル | `0`、`-1`、`true`、`"Mio"`、`0.5` | リテラルと等しい値 |
| 範囲 | `3..=5`、`0..10`、`6..`、`..=2` | 範囲内の整数 |
| パス | `Route::None`、`ORIGIN`、`Self::EMPTY` | ユニットバリアント、ユニット構造体、定数 |
| タプル | `(a, _, true)`、`(first, ..)` | タプル（要素ごとに照合） |
| タプル構造体 / バリアント | `Some(x)`、`EntityId(id)`、`Pair(a, ..)` | タプル構造体またはタプルバリアント（フィールドごとに照合） |
| 構造体 / 構造体バリアント | `Point { x, y: 0 }`、`Shape::Rect { w, .. }` | 構造体または構造体形式のバリアント（フィールド名で照合） |
| 選択 | `Map::A \| Map::B`、`\| 1 \| 2` | いずれかの候補に一致する値 |
| 括弧 | `(Some(_) \| None)` | 内側のパターンと同じ |

スライスや配列のパターン（`[a, b]`）、参照パターン（`&x`）、`ref` や `ref mut` による束縛、`name @ pattern` による束縛はありません。

### 束縛 {#bindings}

識別子のパターンは新しい変数を束縛します。ただし、その名前がスコープ内のユニット構造体、ユニットバリアント、定数を指す場合は、その値と比較するパスパターンになります。この点は Rust と同じです。

```kis
const LIMIT: u32 = 3;

const fn at_limit(n: u32) -> bool {
    match n {
        LIMIT => true,   // the constant `LIMIT`, not a new binding
        _ => false,
    }
}
```

`mut x` と書くと可変な束縛になります。1 つのパターンで同じ名前を 2 回束縛するとエラー `E1024` になります。選択パターン `A | B` では、どの候補も同じ名前を束縛しなければなりません（`E1025`）。`static` はパターンに使えません（`E2035`）。

`&T` や `&mut T` 型の値を束縛以外のパターンと照合すると、参照を透過して中身と照合します。このとき内側の束縛には、値の一部への参照（`&T` または `&mut T`）が入ります。Rust の既定の束縛モードと同じ動作です。

### リテラルパターン {#literal-patterns}

整数リテラルは、照合する型に収まる値でなければならず（`E2013`）、負の値も書けます。文字列リテラルは `Text` に、十進数リテラルは `Decimal` に、`true` と `false` は `bool` に一致します。照合する値と型の異なるリテラルを書くとエラー `E2001` になります。

### 範囲パターン {#range-patterns}

```kis
match AFFECTION_MIO {
    0 => MioIgnores(),
    1..=2 => MioShrugs(),
    3.. => MioSmiles(),
}
```

| 形 | 一致するもの |
| -- | ------------ |
| `a..=b` | `a` から `b` まで（両端を含む） |
| `a..b` | `a` から `b` まで（`b` を含まない） |
| `a..` | `a` 以上 |
| `..=b` | `b` 以下 |

両端には、整数リテラル（負の値も可）か、整数定数へのパスを書きます。範囲パターンが一致するのは整数（Rust の整数と `Int<lo, hi>`）だけで、それ以外の型に使うと `E2001` になります。`..b` というパターンはありません。`..` 単独は、次に説明する残余パターンです。

### 残余パターン {#rest-patterns}

タプル、タプル構造体、構造体のパターンの中の `..` は、書かなかったフィールドすべてを表します（`(first, ..)`、`Pair(a, ..)`、`Shape::Rect { w, .. }`）。タプルやタプル構造体のパターンでは、1 回だけ任意の位置に書けます。たとえば `(.., last)` は最後の要素と照合します。構造体パターンでは末尾に書きます。

### 構造体パターン {#struct-patterns}

`Point { x, y: 0 }` は、`y` が 0 の `Point` に一致し、`x` を束縛します。フィールド名だけを書いた場合（`x`、`mut x`）は同名の変数を束縛し、`field: pattern` と書くとフィールドをそのパターンと照合します。書かなかったフィールドは何にでも一致します。Rust と違って末尾の `..` は省略できますが、省略していることを明示するために書いてもかまいません。存在しないフィールドを書くと `E2020` になります。形の合わないパターン（構造体バリアントにタプルパターンを使う、タプルパターンのフィールド数が合わない、バリアントの代わりに enum 名を書く）は `E2035` になります。

## `match` と網羅性 {#match-and-exhaustiveness}

```kix
match (VISITED_A, VISITED_B) {
    (true, true) => FestivalEnd(),
    (true, false) | (false, true) => s!(t!["One more stall."]),
    (false, false) => {}
}
```

`match` のアームは `pattern => expression` と書き、ガードを付けて `pattern if condition => expression` とも書けます。アームは上から順に試し、パターンが一致してガードが真になった最初のアームを実行します。アームはカンマで区切りますが、本体がブロックのアームの後ではカンマを省略できます。

`match` は**網羅的**でなければなりません。検査対象の型のどの値も、いずれかのアームに一致する必要があります（`E2037`）。違反した場合は、どのアームにも一致しない値をメッセージで示します。前のアームですでに網羅されていて決して実行されないアームは、警告 `W2039` になります。

網羅性の検査でコンパイラが把握している値は、型ごとに次のとおりです。

| 型 | 検査が把握する値 |
| -- | ---------------- |
| `bool` | `true`、`false` |
| `Int<lo, hi>` | ちょうど `lo` から `hi` まで。`Int<0, 2>` なら `_` なしで `0`、`1`、`2` のアームがあれば網羅できる |
| Rust の整数 | 型の全範囲。`u8` の `match` には `255` までのアームか `_` が必要 |
| enum | バリアント。フィールドの中まで再帰的に調べる |
| 構造体、タプル、配列 | 形は 1 通り。フィールドの中まで再帰的に調べる |
| `&T`、`&mut T` | `T` の値 |
| `Text`、`String`、`Decimal`、`Rat`、ジェネリクスパラメータ、その他の組み込み型 | 無制限。リテラルはその値しか網羅しないので、`_` か束縛のアームが必要 |

ガードは考慮しません。ガード付きのアームは、検査の上では何も網羅しないものとして扱います。パターンに使った定数は、初期化子がリテラル、コンストラクター、またはそれらからなるタプルや構造体であれば、その値を網羅します。それ以外の場合は、その定数自身だけを網羅します。

`choice!{…}` の[選択肢](./forms.md#choice)は普通の enum の値なので、選択肢に対する `match` もほかと同じように検査します。選択肢のアームがないバリアントも、個別に処理するか `_` で網羅する必要があります。

## 反駁可能性 {#refutability}

型のすべての値に一致するパターンを**反駁不能**といいます。`let`、`for`、引数のパターンは反駁不能でなければなりません（`E2038`）。

```kis
let (a, b) = pair;          // irrefutable
let Point { x, .. } = p;    // irrefutable
let Some(v) = maybe;        // E2038: `None` is not covered
```

反駁可能なパターンには `if let` か `match` を使います。

```kis
if let Some(v) = maybe {
    use_value(v);
}
```

`let … else` はありません。また、`if let` を `&&` で他の条件とつなげることもできません。
