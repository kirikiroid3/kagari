title: "数値"
---

数値には 2 つの系統があります。**有界整数** `Int<lo, hi>` は、物語が実行時に保持できる唯一の数値型です。チューリング完全な種別では、これに加えて **Rust の整数**と、整数以外を正確に表す `Decimal` と `Rat` の 2 つの型も使えます。浮動小数点数はありません。浮動小数点数は `Eq` にならず（`NaN != NaN`）、画面は等価性で比較できなければならないからです。浮動小数点数の代わりには `Decimal` を、正確な分数には `Rat` を使います。

| 型 | 値 | 実行時に保持できる種別 |
| -- | -- | ---------------------- |
| `Int<lo, hi>` | `lo` から `hi` までの整数（両端を含む） | すべての種別 |
| `u8` … `u128`、`i8` … `i128`、`usize`、`isize` | Rust と同じ | `fn`、`const fn` |
| `Decimal` | 正確な十進数 | `fn`、`const fn` |
| `Rat` | 正確な分数 | `fn`、`const fn` |

これらの型の定数式は、値がコンパイル時に決まるため、`pushdown fn` の中にも書けます。レンダー関数の中の `fade(ms(500))` がその例です。`pushdown fn` でできないのは、これらの型の値を実行時に保持することです。これらの型のローカル変数、パラメータ、戻り値、物語変数はエラーになります（[有限型](../concepts/kinds.md#finite-types)を参照）。

## `Int<lo, hi>` {#intlo-hi}

```kis
static mut AFFECTION_MIO: Int<0, 5> = 0;
```

`Int<lo, hi>` はプリミティブ型で、宣言した範囲（両端を含む）の整数を表します。

- `lo` と `hi` は `i64` に収まる[型レベル定数](./types.md#type-level-constants)で、`lo <= hi` でなければなりません（[`E2004`](../../diagnostics/types.md#e2004)）。
- 既定の範囲はなく、`Int` 型には必ず境界を書きます。
- アナライザは物語変数を、範囲を表すのに必要なビット数だけで表現します。たとえば 0〜5 のカウンタは 3 ビットです。値が収まる最小の範囲を指定してください。

パターンではリテラルや範囲で `Int` の値と照合できるので、しきい値による分岐は次のように書きます。

```kis
match AFFECTION_MIO {
    3..=5 => MioSmiles(),
    _ => MioShrugs(),
}
```

## 整数リテラル {#integer-literals}

接尾辞のない整数リテラルの型は「整数 `n`」という柔軟なものです。文脈が期待する整数型（`Int<lo, hi>` または Rust の整数）の範囲に `n` が含まれていれば、その型になります。含まれなければエラー [`E2013`](../../diagnostics/types.md#e2013) です。型を決める手がかりがなければ、Rust と同じく `i32` になります。接尾辞を付けると型が固定され、`5u8` は `u8` です。整数リテラルが `Decimal` や `Rat` になることはないので、`1` ではなく `1.0` と書きます。

```kis
let a: Int<0, 5> = 3;     // Int<0, 5>
let b: u32 = 3;           // u32
let c = 3u8;              // u8
let d: Int<0, 5> = 9;     // E2013: 9 does not fit
let mut e = 0;            // i32
```

`i32` は[有限型](../concepts/kinds.md#finite-types)ではありません。そのため `pushdown fn` の中で、リテラル以外に型の手がかりがないローカル変数はエラー [`E3008`](../../diagnostics/kinds.md#e3008) になります。物語のカウンタには `let mut laps: Int<0, 3> = 0;` のように型を書いてください。

リテラルどうしの演算はリテラルのまま計算され、`2 * 3` は「整数 6」になります。コンパイラは整数を 128 ビットで表すため、`i128::MAX` を超える `u128` の値はリテラルとして書けません。

## `Int` の算術 {#arithmetic-on-int}

*暫定。* 有界整数の算術は正確です。結果の型は、とりうる結果すべてを含む範囲になるため、実行時にオーバーフローすることはありません。

| 式（`a: Int<l1, h1>`、`b: Int<l2, h2>`） | 型 |
| ---------------------------------------- | -- |
| `a + b` | `Int<l1 + l2, h1 + h2>` |
| `a - b` | `Int<l1 - h2, h1 - l2>` |
| `a * b` | 4 つの端点どうしの積をすべて含む最小の範囲 |
| `a / b` | 4 つの端点どうしの商をすべて含む最小の範囲 |
| `a % b` | 被除数と「除数の絶対値の最大値 − 1」で抑えた範囲 |
| `-a` | `Int<-h1, -l1>` |
| `a == b`、`a < b`、… | `bool` |

- 除算は 0 方向に切り捨てます。`%` の符号は、Rust と同じく被除数の符号に従います。
- `/` と `%` の除数の範囲に 0 が含まれてはいけません（[`E2016`](../../diagnostics/types.md#e2016)）。先に `match` などで型を狭めてください。
- ビット演算子 `& | ^ << >>` と `!` は `Int` には定義されていません（[`E2015`](../../diagnostics/types.md#e2015)）。
- 1 つの演算や比較の中で `Int` と Rust の整数を混ぜることはできません（[`E2014`](../../diagnostics/types.md#e2014)）。先にどちらかに変換してください。
- 結果の範囲が 128 ビットに収まらない場合はエラー [`E2015`](../../diagnostics/types.md#e2015) になります。

### 拡大と複合代入 {#widening-and-compound-assignment}

値は、自身の範囲を含む範囲の `Int` 型へ暗黙に変換されます。たとえば `Int<1, 6>` の値は `Int<0, 10>` に格納できます。範囲がより広い値を格納するには、`.saturate()` で変換します（[変換](#conversions)を参照）。

**複合代入は飽和します。** `Int` の変数に対する `x += e`、`x -= e`、`x *= e`、`x /= e`、`x %= e` は、正確な結果を計算してから `x` の境界に切り詰めます。`x += 1` は `x = (x + 1).saturate()` と同じです。右辺はどの `Int` でもかまいません。飽和があるので、どのステップも必ず結果を持ちます。これは定義された動作であり、実行時エラーにはなりません。`/=` と `%=` の除数の範囲に 0 が含まれてはならず、ビット演算の複合代入は `Int` には定義されていません。

```kis
static mut AFFECTION_MIO: Int<0, 5> = 0;

pushdown fn praise() {
    AFFECTION_MIO += 1;     // stays 5 once it is 5
}
```

黙って飽和するカウンタは、範囲が狭すぎるサインであることが少なくありません。

## 変換 {#conversions}

整数型が暗黙に変換されるのは、リテラルの場合と、`Int` 型からより広い `Int` 型への拡大の場合だけです。標準ライブラリのトレイト `Integer` は `Int<lo, hi>` とすべての Rust の整数が実装しており、明示的な変換を 2 つ提供します。変換先の型は文脈から推論させるか、ターボフィッシュ（`x.into::<u32>()`）で指定します。

| メソッド | 結果 |
| -------- | ---- |
| `x.into()` | 同じ値を整数型または `Decimal` として返す。変換元の型のすべての値が変換先の型に収まらない場合はコンパイルエラー（[`E2018`](../../diagnostics/types.md#e2018)）。整数はすべて `Decimal` に収まる |
| `x.saturate()` | 変換先の型の範囲に切り詰めた値。変換先は整数型に限る |

```kis
const fn label_width(chars: Int<0, 40>) -> u32 {
    let n: u32 = chars.into();      // every Int<0, 40> fits in u32
    n * 16
}

fn set_level(level: u32) {
    let level: Int<0, 100> = level.saturate();
    MUSIC.set(volume(level));
}

const fn moon_angle(day: Int<0, 7>) -> Decimal {
    let back: Decimal = (7 - day).into();       // exact
    back * 5.0 + Decimal::from_int(day)         // the same conversion
}
```

`as` によるキャストはありません（[`E2019`](../../diagnostics/types.md#e2019)）。`Decimal::from_int(x)` は任意の整数を正確に `Decimal` に変換するもので、変換先が `Decimal` の `x.into()` と同じです。`Rat::new` は 2 つの `i128` から `Rat` を作り、`Rat::to_decimal` は `Rat` を `Decimal` に変換します。`Decimal` や `Rat` から整数へ変換する手段はありません。

## Rust の整数 {#rust-integers}

チューリング完全な種別では、Rust の整数型 `u8`、`u16`、`u32`、`u64`、`u128`、`i8`、`i16`、`i32`、`i64`、`i128`、`usize`、`isize` を使えます。`usize` と `isize` はどのプラットフォームでも 64 ビットです。

| 演算子 | 意味 |
| ------ | ---- |
| `+ - * / %` | 算術。両辺は同じ型 |
| `& \| ^` | ビット積、ビット和、ビット排他的論理和 |
| `<< >>` | シフト。シフト量はどの整数型でもよい |
| `-x` | 符号反転。符号付き型のみ（[`E2015`](../../diagnostics/types.md#e2015)） |
| `!x` | ビット否定 |
| `== != < <= > >=` | 比較 |

- 算術は検査付きです。オーバーフロー、ゼロ除算、型の範囲外の結果はエラーになり（[エラー](#errors-at-compile-time-and-at-runtime)を参照）、黙って折り返すことはありません。
- `/` は 0 方向に切り捨て、`%` の符号は被除数に従います。
- シフト量は型のビット幅未満でなければなりません。`<<` ではみ出したビットは捨てられ、符号付き型の `>>` は算術シフトです。
- 異なる Rust の整数型どうしは混ぜられません。`.into()` か `.saturate()` で変換してください。

## `Decimal` {#decimal}

`Decimal` は正確な十進数です。不透明度、音量、レイアウト上の位置など、もともと十進で表す値に使います。`0.5` や `1.0` のように小数点を含むリテラルは `Decimal` になります。浮動小数点数の代わりとなる型で、`Eq` を満たします。`0.1 + 0.2 == 0.3` は `true` です。

| 演算子 | 意味 |
| ------ | ---- |
| `+ - *` | 正確 |
| `/` | 正確に計算したあと、小数点以下 7 桁までを残して 0 方向に切り捨てる。`1.0 / 3.0` は `0.3333333` |
| `-x` | 符号反転 |
| `== != < <= > >=` | 比較 |

`Decimal` に `%` はありません。仮数部は 128 ビットで、収まらない結果はオーバーフローエラーになります。

## `Rat` {#rat}

`Rat` は正確な有理数で、既約の分子と正の分母（どちらも `i128`）で表します。`Rat` のリテラルはなく、値は `Rat::new(num, den)` で作ります。分数は約分され、`Rat::new(2, -4)` は `-1/2` になります。`den == 0` はゼロ除算です。

演算子は `Decimal` と同じですが、`/` も正確です。`Rat::to_decimal` は `Decimal` への変換で、整数部と小数点以下最大 7 桁を残して 0 方向に切り捨てます（`Rat::new(1, 3).to_decimal()` は `0.3333333`、`Rat::new(-2, 3).to_decimal()` は `-0.6666666`）。

```kis
const fn rats() -> Rat {
    let a = Rat::new(1, 3);
    a * a - a / Rat::new(2, 1)      // 1/9 - 1/6 = -1/18
}
```

## コンパイル時と実行時のエラー {#errors-at-compile-time-and-at-runtime}

| エラー | コンパイル時の評価中 | 実行時 |
| ------ | -------------------- | ------ |
| オーバーフロー、型の範囲外の結果、不正なシフト量 | [`E4001`](../../diagnostics/eval.md#e4001) | VM パニック |
| ゼロ除算、`Rat::new(_, 0)` | [`E4002`](../../diagnostics/eval.md#e4002) | VM パニック |

VM パニックは定義済みのゲーム停止で、[ランタイム](../tools/runtime.md)が処理します。コンパイル時に評価されるコード（定数、レンダー関数、物語から呼ぶ `const fn`）では、これらのエラーは値が必要になった呼び出しの位置で診断として報告されます。そのため、物語そのものがこの形で失敗することはありません。`Int<lo, hi>` の複合代入は飽和するので、失敗しません。
