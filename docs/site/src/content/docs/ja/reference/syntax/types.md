title: "型"
---

Kagari は静的型付けの言語で、どの値の型もコンパイル時に決まります。アイテムのシグネチャには型を明記し、関数本体の中では型を推論します。

## 型の書き方 {#type-expressions}

| 構文 | 型 |
| ---- | -- |
| `Path`、`Path<Args>` | 名前で指す型（プリミティブ、構造体、列挙型、型エイリアス、ジェネリクスパラメータ） |
| `()` | ユニット型（空のタプル） |
| `(A,)`、`(A, B)`、… | タプル |
| `(A)` | `A` と同じ。括弧はまとめるだけ |
| `[T; N]` | 要素数 `N` の配列 |
| `&T`、`&mut T` | 共有参照、可変参照 |
| `fn(A) -> R`、`const fn(A) -> R`、`pushdown fn(A) -> R`、`scene fn(A) -> R` | 関数ポインタ |
| `Fn(A) -> R`、`const Fn(A) -> R`、`pushdown Fn(A) -> R` | クロージャ型 |
| `_` | プレースホルダ（型を推論させる） |
| `Self` | `impl` の対象の型 |

`-> R` を省いた関数ポインタ型やクロージャ型は `()` を返します。プレースホルダ `_` は、本体の中の `let` の型注釈やジェネリクス引数には書けますが、アイテムのシグネチャには書けません（[`E2011`](../../diagnostics/types.md#e2011)）。スライス型 `[T]`、`str`、`!` 型の構文、`dyn` 型や `impl Trait` 型、生ポインタはありません。

## 型の一覧 {#overview}

| 型 | 値 | 備考 |
| -- | -- | ---- |
| `bool` | `true`、`false` | |
| `()` | `()` | 結果を返さないブロックや関数の値 |
| `Int<lo, hi>` | `lo` から `hi` までの整数 | プリミティブ。[数値](./numbers.md#intlo-hi)を参照 |
| `u8` … `u128`、`i8` … `i128`、`usize`、`isize` | Rust と同じ | [Rust の整数](./numbers.md#rust-integers)を参照 |
| `Decimal`、`Rat` | 誤差のない十進小数と分数 | [数値](./numbers.md)を参照 |
| `Text` | 定数のテキスト | [Text と String](#text-and-string) を参照 |
| `String` | 実行時に作るテキスト | |
| タプル、配列 | `(bool, Route)`、`[Int<0, 3>; 4]` | |
| `Vec<T>` | 長さが変わるリスト | |
| `Range<T>` | `0..4`、`3..=5` | [範囲](#ranges)を参照 |
| 構造体、列挙型 | ユーザー定義の型と、プレリュードにある `Option<T>`、`Result<T, E>` | |
| 参照 | `&T`、`&mut T` | [値、参照、クロージャ](./values.md#references)を参照 |
| 関数ポインタ、クロージャ | `fn(u32) -> bool`、`Fn(u32) -> bool` | [クロージャ型とポインタ型](./values.md#closure-and-pointer-types)を参照 |
| 組み込み型 | `Screen`、`Narrative`、`Element`、`Setting<T>`、`Meta<T>`、アセット型など | 中身の見えないハンドル。[組み込み型](../special/builtin-types.md)を参照 |

浮動小数点型はありません。また、物語が実行時に保持できるのは[有限型](#finite-types)だけです。

## プリミティブ型 {#primitive-types}

`bool`、`Int`、Rust の整数型 12 種類がプリミティブ型です。プリミティブ型には宣言がなく、名前の解決ではほかのどの名前よりも後に探します（[パス](./modules.md#paths)を参照）。`Int` には必ず境界を 2 つ指定し、ほかのプリミティブ型にはジェネリクス引数を付けません（[`E2005`](../../diagnostics/types.md#e2005)）。ユーザーのコードからプリミティブ型に `impl` を追加することはできません。

## Text と String {#text-and-string}

| 型 | 内容 |
| -- | ---- |
| `Text` | プログラム中に書かれた定数のテキスト。普通の文字列リテラル（`"Mio"`）か、`t![…]` で書くルビやテキスト効果付きのリッチテキスト。文字列リテラルの型は必ず `Text` になる。値はプログラムに書かれたテキストに限られるので `Text` は[有限型](#finite-types)であり、物語が保持できる |
| `String` | `fn` のコードが実行時に組み立てる文字列。有限型ではない |

どちらも `Eq` を実装しています。`Text` は `std::narrative::text`、`String` は `std` で宣言されており、どちらもプレリュードに含まれます。

## タプル、配列、`Vec` {#tuples-arrays-and-vec}

- **タプル** `(A, B, …)` は、型の違う値をひとまとめにします。各フィールドは `.0`、`.1`、… で取り出します。要素が 1 つのタプルは `(A,)` と書きます。`()` はユニット型です。
- **配列** `[T; N]` は、`T` 型の値をちょうど `N` 個まとめたものです。`N` は[型レベル定数](#type-level-constants)です。`[a, b, c]` や `[value; N]` で作り、`a[i]` で要素を取り出します。範囲外の添字を使うと、コンパイル時ならエラー、実行時なら VM パニックになります。
- `Vec<T>` は、実行時に長さが変わるリストです。`Vec::new()`、`push`、`len`、`is_empty`、`get`、`set` が使えます。有限型ではありません。詳しくは[標準ライブラリのリファレンス](../../std/std.md)を参照してください。

## 構造体と列挙型 {#structs-and-enums}

構造体と列挙型は名前で区別する型です。フィールドがまったく同じでも、宣言が別なら別の型になります。ジェネリクスパラメータを付けることもできます。標準ライブラリには `Option<T>`（`None`、`Some(T)`）と `Result<T, E>`（`Ok(T)`、`Err(E)`）があり、各バリアントはプレリュードに含まれます。宣言の書き方は[アイテム](./items.md#structs)を参照してください。

## 範囲 {#ranges}

`a..b` と `a..=b` は、標準ライブラリの構造体 `Range<T>` の値です。

```kis
pub struct Range<T> {
    pub start: T,
    pub end: T,
    pub inclusive: bool,
}
```

`a..b` は `b` を含まず、`a..=b` は `b` を含みます。値として書ける範囲はこの 2 つだけで、`a..` や `..b` などほかの形はエラー [`E2030`](../../diagnostics/types.md#e2030) になります。パターンには別に `a..`、`..=b`、`a..b`、`a..=b` という範囲の形があります（[範囲パターン](./patterns.md#range-patterns)を参照）。ただし `..b` というパターンはなく、パターン中に `..` だけを書くと残余パターンになります。範囲は `for` で順に回せます（[制御フローとループ](./control-flow.md)を参照）。

## ジェネリクス {#generics}

関数、構造体、列挙型、型エイリアス、`impl` ブロックにはジェネリクスパラメータを付けられます。

```kis
struct Pair<T> { a: T, b: T }

fn first<T, const N: usize>(items: [T; N]) -> T {
    items[0]
}
```

- **型パラメータ** `T` には、`T: Eq` や `T: Eq + Integer` のように[境界](#trait-bounds)を付けられます。
- **定数パラメータ** `const N: usize` は、整数型の定数を表します。`Int<lo, hi>` も、`i64` の定数パラメータを 2 つ取るプリミティブ型です。
- ジェネリクス引数は推論に任せることも、明示することもできます。型の中では `Pair<u8>`、式の中ではターボフィッシュを使って `first::<u8, 3>(…)` と書きます。引数の数が合わないとエラー [`E2005`](../../diagnostics/types.md#e2005) になります。
- ジェネリックなコードは**単相化**されます。プログラムで使われている引数の組み合わせごとに、コンパイラがコードを複製します。`pushdown fn` の中では型引数をすべて[有限型](#finite-types)にする必要があり、これによって物語は有限のプログラムに保たれます。
- ライフタイム、`where` 節、既定の引数、ユーザー定義の関連型はありません。

### 型レベル定数 {#type-level-constants}

配列の長さ、`Int` の境界、定数ジェネリクス引数を**型レベル定数**と呼びます。ジェネリクス引数として書くときは、整数リテラル（`Square<8>`）、負のリテラル（`Int<-5, 5>`）、定数パラメータや `const` アイテムの名前（`Int<0, MAX>`）、波括弧で囲んだ式（`Int<0, { MAX * 2 }>`）のどれかを使います。波括弧の中の式に使えるのは、整数リテラル、単項の `-`、`+ - * / %`、最後の式だけでできたブロック、定数パラメータ、同じ条件を満たす式を値に持つ `const` アイテムだけです（[`E2002`](../../diagnostics/types.md#e2002)）。定数を書くべき位置に型を書くとエラー [`E2007`](../../diagnostics/types.md#e2007) になります。

```kis
const MAX: i64 = 5;
static mut TRUST: Int<0, MAX> = 0;
static mut DOUBLE: Int<0, { MAX * 2 }> = 0;
```

## トレイト境界 {#trait-bounds}

境界には標準ライブラリのトレイトを指定します。トレイトを宣言したり実装したりすることはできませんが、境界として要求することはできます。

| トレイト | 実装している型 | 使えるようになるもの |
| -------- | -------------- | -------------------- |
| `Eq` | 構造的に等しさを比べられるすべての型（[等価性](#equality)を参照） | `==`、`!=` |
| `Integer` | `Int<lo, hi>` と Rust の整数型 | `into`、`saturate`（[変換](./numbers.md#conversions)を参照） |
| `FromInteger` | 整数型と `Decimal` | `into` の変換先になれる |
| `RandChoose` | フィールドのない列挙型と `Int<lo, hi>` | `rng_choose::<T>()` |
| `Asset` | アセット型 | `asset::<A>(…)` |
| `Step` | ステップ `Say` と `Choice` | `push_step` と関連型 `Output` |
| `ToText` | `Text`、`String`、`Int<lo, hi>`、Rust の整数型、`Rat`、`Decimal` | `t![…]` 内の埋め込み `{expr}` |

境界を満たさないジェネリクス引数を渡すとエラー [`E2026`](../../diagnostics/types.md#e2026) になります。境界を付けると、そのトレイトのアイテムをパラメータに対して使えるようになります。たとえば `S: Step` なら `S::Output`、`T: Integer` なら `value.into()` が使えます。詳しくは[言語トレイト](../special/traits.md)を参照してください。

## 等価性 {#equality}

`derive` はありません。`==` と `!=` を使うには両辺の型が `Eq` を実装している必要があります（[`E2017`](../../diagnostics/types.md#e2017)）。`Eq` は次の型に自動で実装されます。

- `bool`、`Int<lo, hi>`、Rust の整数型
- フィールドや要素がすべて `Eq` である構造体、列挙型、タプル、配列。構造で比較し、同じ形に組み立てた値どうしが等しくなります。
- 関数ポインタと名前付き関数。同じ関数かどうかで比較します。
- `T` が `Eq` のときの `&T` と `&mut T`。参照先の値を比較します。
- 標準ライブラリで `Eq` と宣言されている組み込み型。`String`、`Vec<T>`（`T` が `Eq` のとき）、`Rat`、`Decimal`、`Text`、`Screen`、アセット型が該当します。

クロージャが `Eq` になることはありません。上に挙げた以外の組み込み型も `Eq` ではありません。

## 有限型 {#finite-types}

物語が実行時に保持できるのは**有限型**だけです。有限型とは、取りうる値が有限個で、コンパイラがそのすべてを列挙できる型のことです。おおまかには次のとおりです。

| 有限型 | 有限型でない |
| ------ | ------------ |
| `bool`、`()`、`Int<lo, hi>` | Rust の整数型、`Rat`、`Decimal` |
| 有限型だけでできた構造体、列挙型、タプル、配列 | `String`、`Vec<T>`、再帰的な型 |
| `Text`、アセット型 | `Screen` などの組み込みのハンドル |
| `pushdown fn`、`scene fn`、`const fn` のポインタ | `fn` のポインタ、クロージャ |
| 有限型 `T` に対する `&T`、`&mut T`（パラメータに限る） | |

ただし定数式は、値がコンパイル時に決まるので、型を問わず物語の中に書けます。正確な規則は[関数種別](../concepts/kinds.md#finite-types)を参照してください。

## 関数ポインタ型とクロージャ型 {#function-pointer-and-closure-types}

関数ポインタ型とクロージャ型には、呼び出す先のコードの[種別](../concepts/kinds.md)が含まれます。そのため、ポインタやクロージャを経由して呼び出しても、呼び出しの規則はそのまま守られます。

| 型 | 入れられるもの |
| -- | -------------- |
| `fn(A) -> R`、`const fn(A) -> R` | 同じ種別の名前付き関数 |
| `pushdown fn(A) -> R` | 名前付きの即時手続き |
| `scene fn(A) -> R` | 名前付きのシーン（構文は*暫定*） |
| `Fn(A) -> R`、`const Fn(A) -> R`、`pushdown Fn(A) -> R` | 同じ種別のクロージャまたは関数（構文は*暫定*） |

型強制も含めた詳しい説明は[値、参照、クロージャ](./values.md#closure-and-pointer-types)にあります。

## 型強制 {#coercions}

ある型の値を書くべき位置に別の型の値を書いた場合、次の暗黙の変換が行われます。

| 変換元 | 変換先 |
| ------ | ------ |
| 整数リテラル | その値を範囲に含む任意の整数型 |
| `Int<l1, h1>` | `l2 <= l1` かつ `h1 <= h2` を満たす `Int<l2, h2>`（範囲の拡大） |
| `&mut T` | `&T` |
| 名前付き関数、タプルのコンストラクター | 種別とシグネチャが同じ関数ポインタ |
| 名前付き関数、関数ポインタ、クロージャ | 種別が同じクロージャ型（シーンは除く） |
| 何もキャプチャしないクロージャ | 種別が同じ関数ポインタ |
| `return`、`break`、`continue`、終わらない `loop` の型 | 任意の型 |

これ以外の型の変換は、`x.into()` のように明示して書きます。

## 型推論 {#type-inference}

本体の中では、Rust と同じく使われ方から型を推論します。一方、アイテムのシグネチャは推論しません。パラメータの型、戻り値の型、定数や static の型は必ず書きます。推論だけでは型が決まらないときは型注釈が必要です（[`E2029`](../../diagnostics/types.md#e2029)）。

```kis
fn demo() {
    let names: Vec<Text> = Vec::new();
    let level: Int<0, 5> = 3;
}
```
