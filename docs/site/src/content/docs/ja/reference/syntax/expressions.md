title: "式と文"
---

Kagari は Rust の構文を借りた式指向の言語です。ブロックも式で、`if` や `match` は値を返し、文は `;` で終わります。この章では、パーサーが受け付ける式をすべて挙げ、コンパイラが課す規則を説明します。制御フローの式（`if`、`match`、ループ、`break`、`continue`、`return`）は[制御フローとループ](./control-flow.md)で、`.kix` の組み込み構文（`s!(…)`、`t![…]`、`column![…]` など）は[組み込み構文](./forms.md)で扱います。

## ブロックと文 {#blocks-and-statements}

```kis
const fn label_width(chars: Int<0, 40>) -> u32 {
    let n: u32 = chars.into();
    let padding = 8;
    n * 16 + padding
}
```

ブロック `{ … }` は中の文を順に実行します。最後の式の後ろに `;` がなければ、その式の値がブロックの値になり、`;` があればブロックの値は `()` です。ブロックはスコープを作るので、中の `let` 文で導入した束縛は閉じ括弧 `}` までしか使えません。

ブロックには次のものを書けます。

| 文 | 形 | 備考 |
| -- | -- | ---- |
| `let` 文 | `let pat: Type = expr;` | [後述](#let-and-let-mut) |
| 式文 | `expr;` | 値は捨てられます。`#[must_use]` の値を捨てると警告 `W3023` |
| ブロック状の式 | `if …`、`match …`、`loop`、`while`、`for`、`{ … }`、`name!{…}` 形式の組み込み構文 | `;` は不要 |
| アイテム | `fn`、`struct`、`enum`、`const`、`use` など | ブロック内で宣言するアイテム。ファイルモジュール（`mod name;`）はエラー `E1005` |
| 空文 | `;` | 何もしません |

**ブロック状の式はそこで文が終わります。** 文の先頭に置いたブロック、`if`、`match`、`loop`、`while`、`for`、`choice!{…}` のような波括弧の組み込み構文は、`;` がなくても一つの文として完結します。後ろに何か書いても式の続きにはなりません。そのため `if c { a } else { b } - 1` は二つの文になり、`{ … } (x)` も呼び出しではなく、ブロックの後に括弧付きの式が並んでいるだけです。値として使いたいときは `(if c { a } else { b }) - 1` と書きます。

二つの式文の間に `;` がないと構文エラー（`E0001`）になります。

### `let` と `let mut` {#let-and-let-mut}

```kis
let n = 3;
let mut total: u32 = 0;
let (x, y) = (1, 2);
let Point { x: px, y: py } = origin();
let mut later: bool;
```

`let` は、パターン中の変数を値に束縛します。

- パターンは反駁不能、つまり型のどの値にも一致するものでなければなりません（`E2038`）。詳しくは[パターン](./patterns.md#refutability)を参照してください。
- 型注釈 `: Type` は省略でき、省略すると型は推論されます。
- 初期化子 `= expr` も省略できます。ただし初期化子なしで宣言した束縛は、読む前に代入が必要です。代入前に読むと実行時パニックが起き、ゲームが止まります。
- パターンで `mut` を付けない限り、束縛は不変です。不変の束縛に代入するとエラー `E3017` になります。**初期化子なしで宣言した束縛への最初の代入もこれに含まれる**ので、そうした束縛は `let mut` で宣言してください。
- `pushdown fn` の中のローカル変数には[有限型](../concepts/kinds.md#finite-types)の値しか入れられず（`E3008`）、クロージャや参照も入れられません（`E3015`、`E3014`）。

## リテラル {#literals}

| リテラル | 例 | 型 |
| -------- | -- | -- |
| 整数 | `42`、`1_000`、`0xFF`、`0o17`、`0b1010`、`5u8`、`300i64` | 文脈から推論した整数型。接尾辞を付けると型が固定されます。[数値](./numbers.md)を参照 |
| 小数 | `0.5`、`1.0`、`12.75` | `Decimal` |
| 文字列 | `"Mio"`、`"line one\nline two"` | `Text` |
| 真偽値 | `true`、`false` | `bool` |
| ユニット | `()` | `()` |

文字、バイト、生文字列、浮動小数点数のリテラルはなく、指数表記も使えません。`-5` は `5` に単項 `-` を適用した式ですが、型付けでは一つの負のリテラルとして扱います。エスケープ、接尾辞、桁区切りなど、トークンの厳密な構文は[字句構造](./lexical.md)を参照してください。

## パス {#paths}

```kis
ROUTE
Route::Azusa
std::time::ms(500)
Self::new()
super::helpers::clamp(x)
asset::<ImageAsset>("bg/room.png")
rng_choose::<Coin>()
```

パスは、ローカル変数、引数、アイテム（関数、定数、static、ユニット構造体、enum のバリアント）、関連アイテムを指す名前です。セグメントは `::` で区切ります。`self`、`super`、`crate`、`Self` の意味は Rust と同じです（[ソースファイルとモジュール](./modules.md)を参照）。

式の中でジェネリクス引数を渡すときは、ターボフィッシュ `::<…>` を使います。ジェネリクス引数に書けるのは、型、整数リテラル（`-` を付けてもよい）、[型レベル定数](./constants.md#type-level-constants)を入れたブロック `{ … }` のいずれかです。

式の中のパスがモジュールや名前付きフィールドの構造体など、値でないものを指しているとエラー `E2009` になります。未知の名前はエラー `E1016` です。

## 演算子 {#operators}

### 優先順位と結合性 {#precedence-and-associativity}

パーサーの実装に沿って、結合の強いものから順に並べています。

| 演算子 | 結合性 |
| ------ | ------ |
| パス、リテラル、`( … )`、ブロック、組み込み構文、`if`、`match`、ループ | — |
| フィールド `a.b`、タプルのフィールド `a.0`、メソッド呼び出し `a.m(…)`、呼び出し `f(…)`、添字 `a[i]`、`?` | 左から右 |
| 単項 `-`、`!`、`*`（参照外し）、`&`、`&mut` | 前置 |
| `as`（常にエラー `E2019`） | 左 |
| `*` `/` `%` | 左 |
| `+` `-` | 左 |
| `<<` `>>` | 左 |
| `&` | 左 |
| `^` | 左 |
| `\|` | 左 |
| `==` `!=` `<` `>` `<=` `>=` | なし（`a < b < c` は構文エラー） |
| `&&` | 左 |
| `\|\|` | 左 |
| `..` `..=` | 左（範囲を連ねて書くことは想定していません） |
| `=` `+=` `-=` `*=` `/=` `%=` `^=` `&=` `\|=` `<<=` `>>=` | 右 |
| `return`、`break`、クロージャ `\|…\| body` | できるだけ右まで及ぶ |

Rust の表とほぼ同じですが、Rust では非結合の範囲演算子が、Kagari では左結合です。比較演算子は連ねて書けないので、`a < b && b < c` と書いてください。

### オペランドの型 {#operand-types}

| 演算子 | オペランド | 結果 |
| ------ | ---------- | ---- |
| `+` `-` `*` `/` `%` | 同じ Rust 整数型どうし、`Int` どうし、`Decimal` どうし、`Rat` どうし | [数値](./numbers.md)を参照。`Int` の演算では結果の範囲も計算します |
| `&` `\|` `^` | 同じ Rust 整数型どうし、または `bool` どうし | オペランドと同じ型 |
| `<<` `>>` | Rust 整数二つ（型が違ってもよい） | 左オペランドの型 |
| `==` `!=` | `Eq` を満たす同じ型どうし（満たさなければ `E2017`） | `bool` |
| `<` `>` `<=` `>=` | 同じ型の整数どうし、`Int` どうし、`Decimal` どうし、`Rat` どうし | `bool` |
| `&&` `\|\|` | `bool` どうし。右辺は必要なときだけ評価 | `bool` |
| 単項 `-` | 符号付き Rust 整数、`Int`（範囲の符号も反転）、`Decimal`、`Rat` | オペランドと同じ型 |
| 単項 `!` | `bool`（論理否定）または Rust 整数（ビット反転） | オペランドと同じ型 |
| 単項 `*` | 参照 `&T` または `&mut T`（それ以外は `E2033`） | `T` |
| `&e`、`&mut e` | 任意の式。`&mut` には可変な場所が必要（`E3017`） | `&T`、`&mut T` |

整数型が暗黙に混ざることはありません。`Int` と Rust 整数、あるいは異なる Rust 整数型どうしに演算子を使うとエラーになります（`E2014`、`E2001`）。どちらかを `.into()` か `.saturate()` で変換してください。ビット演算子は Rust 整数専用で、`Int` に使うとエラー `E2015` になります。除数の `Int` の範囲に 0 が含まれる除算・剰余はエラー `E2016` です。大小比較は数値にしか定義されておらず、タプル、`Text`、enum に `<` を使うとエラー `E2015` になります。`Eq` 型の等価比較は構造的に行います。詳しくは[言語トレイト](../special/traits.md)を参照してください。

### `as` {#as}

`as` は Rust と同じ優先順位で構文解析しますが、キャストはすべてエラー（`E2019`）になります。整数の変換には `x.into()`（情報を失わない変換で、コンパイル時に検査）か `x.saturate()`（範囲内に丸める変換）を使います。[数値](./numbers.md)を参照してください。

## 代入と複合代入 {#assignment-and-compound-assignment}

```kis
total = 0;
AFFECTION_MIO += 1;
point.x = 10;
scores[i] -= 1;
```

`place = value` は値を格納します。`place op= value` は、演算子 `+ - * / % ^ & | << >>` のいずれについても `place = place op value` と同じ意味です。代入式の型は `()` です。

左辺には可変な場所しか書けません（`E3017`）。可変な場所とは次のものです。

- `mut` を付けて宣言したローカル変数や引数
- `pushdown fn` の中の物語変数（`static mut`）
- 可変な場所のフィールド `a.b` や要素 `a[i]`
- `r` が `&mut T` のときの `*r`、および `&mut T` からたどったフィールドや要素

定数、不変の `static`、呼び出し結果のような一時的な値、`&T` からたどったものには代入できません。

`Int` の場所への複合代入は、型の上限・下限で**飽和**します。右辺にはどんな `Int` 値でも書けます。たとえば値が 5 の `Int<0, 5>` に `AFFECTION_MIO += 1` を実行しても、値は 5 のままです。[数値](./numbers.md)を参照してください。

## 呼び出しとメソッド呼び出し {#calls-and-method-calls}

```kis
fade(ms(500))
Confession()
screen.entity(AZUSA).image()
x.into()
scores.get(0)
```

`f(a, b)` は関数、関数ポインタ、クロージャを呼び出します。`f` の位置には任意の式を書けます。引数の数が合わないとエラー `E2024`、呼び出せない値を呼び出すとエラー `E2025` になります。どの関数種別からどの関数種別を呼べるかは[関数種別](../concepts/kinds.md#call-rules)を参照してください。

`receiver.method(args)` は、レシーバーの型の `impl` で宣言したメソッドか、標準のトレイトが提供するメソッドを呼び出します。レシーバーは、メソッドの `self`、`&self`、`&mut self` に合わせて自動的に借用・参照外しされます。`&mut self` のメソッドを呼ぶには、レシーバーが可変な場所でなければなりません（`E3017`）。関連関数は `Type::function(args)` で呼び出します。メソッドにジェネリクス引数を渡すときも `x.m::<T>(…)` のようにターボフィッシュを使います。未知のメソッドはエラー `E2022`、`self` を取らない関連関数をメソッド構文で呼ぶとエラー `E2023` になります。

## フィールドと添字 {#fields-and-indexing}

```kis
point.x
pair.0
nested.0.1
grid[row][col]
```

- `a.name` は名前付きフィールドを、`a.0`、`a.1` などはタプルやタプル構造体のフィールドを読みます。`t.0.1` はフィールドアクセスを 2 回行う式です。参照は自動的に参照外しされます。未知のフィールドはエラー `E2020` です。
- `a[i]` は配列か `Vec<T>` の要素を読みます（それ以外の型ではエラー `E2032`）。添字は整数で、整数リテラルの添字は `usize` になります。末尾を越える添字は実行時パニックになり、[定数評価](./constants.md#const-evaluation-errors)の途中ならエラー `E4005` になります。

## 構造体、タプル、配列の式 {#struct-tuple-and-array-expressions}

```kis
Point { x: 1, y: 2 }
Point { x, y }
Shape::Rect { w: 10, h: 20 }
EntityId(216)
Route::None
(1, true)
(5,)
[1, 2, 3]
[false; 8]
```

| 式 | 備考 |
| -- | ---- |
| `Path { field: value, … }` | 構造体、または構造体形式の enum バリアント。フィールドはすべて指定が必要（`E2021`）、未知のフィールドは `E2020`。`Path { x }` は `Path { x: x }` の省略形。構造体更新構文 `..base` はなし |
| `Path(a, b)` | タプル構造体またはタプルバリアント。コンストラクターは関数として使えます |
| `Path` | ユニット構造体またはユニットバリアント |
| `(a, b)`、`(a,)`、`()` | タプル。要素が一つのタプルには末尾のカンマが必要で、`(a)` は単なる `a` |
| `[a, b, c]` | 並べた要素からなる配列。要素はすべて同じ型 |
| `[value; N]` | 同じ値を `N` 個並べた配列。`N` は[型レベル定数](./constants.md#type-level-constants) |

`if` や `while` の条件、`match` の対象、`for` の反復対象には、構造体式をそのまま書けません。`{` が本体の始まりと解釈されてしまうためです。`if p == (Point { x: 0, y: 0 }) { … }` のように括弧で囲んでください。

## 範囲 {#ranges}

```kis
0..4      // 0, 1, 2, 3
3..=5     // 3, 4, 5
```

`a..b`（終端を含まない）と `a..=b`（終端を含む）は `Range<T>` を作ります。`Range<T>` は std の構造体で、`start`、`end`、`inclusive` のフィールドがあります。`T` は両端の値を変換できる型です。`0..7` は、使われ方から別の整数型が求められない限り `Range<i32>` になり、`last: Int<0, 7>` のとき `0..last` は `Range<Int<0, 7>>` になります。範囲式には両端が必要で、`a..`、`..b`、`..=b`、`..` はエラー `E2030` です。パターンとしては `a..` と `..=b` が使えますが、`..b` はなく、`..` 単独は残余パターンになります（[範囲パターン](./patterns.md#range-patterns)を参照）。範囲は主に `for` ループで使います（[制御フローとループ](./control-flow.md#for-loops)を参照）。

## クロージャ {#closures}

```kis
|x| x + 1
|| nav::back()
|a: u32, b: u32| a * b
|mut screen| { screen.hud().text_window().change(Visibility::Hidden).apply_animation(instant()); screen }
|v| -> u32 { v * 2 }
```

`|params| body` がクロージャです。引数は反駁不能なパターンで、型は省略できます。`||` は引数のないクロージャです。本体には任意の式を書けますが、戻り値の型 `-> T` を書くときは本体をブロックにします。`move` はなく、クロージャは使う変数を常に値でキャプチャします。

クロージャで何ができるか、どう型付けされるか（`Fn(A) -> B`、`pushdown Fn(A) -> B`、`const Fn(A) -> B`）は[値、参照、クロージャ](./values.md)で説明しています。要点は次のとおりです。

- 何もキャプチャしないクロージャは、同じ種別の関数ポインタに変換できます。レンダーをその場に書けるのはこの仕組みのおかげです。関数ポインタが必要な場所に、何かをキャプチャするクロージャを書くとエラー `E2036` になります。
- `pushdown fn` の中では、クロージャは第二級の値です。引数として渡したり呼び出したりはできますが、ローカル変数に入れる、返す、キャプチャすることはできません（`E3015`）。

## `?` 演算子 {#the-try-operator}

```kis
fn first_score(scores: Vec<u32>) -> Option<u32> {
    let first = scores.get(0)?;
    Some(first * 10)
}
```

`Option<T>` に `expr?` を使うと、`Some` なら中の `T` を取り出し、`None` なら囲んでいる関数から `None` を返します。`Result<T, E>` の場合は、`Ok` なら中の `T` を取り出し、`Err` ならその `Err` を返します。囲んでいる関数の戻り値は `Option`、またはエラー型が同じ `Result` でなければなりません。この条件を満たさない場合や、ほかの型に使った場合はエラー `E2034` になります。`?` を含む式は定数式になりません。
