---
title: "用語集"
---

このリファレンスで使う用語を、英数字で始まるものを先に、その後は五十音順に並べています。括弧内は英語の用語です。各項目の末尾に、その用語を定義している章へのリンクがあります。標準ライブラリの用語は、標準ライブラリのリファレンスにリンクしています。

- **`const fn`**（`const fn`）。純粋で決定的な、チューリング完全なコードのための関数種別です。レンダー、定数、補助関数を書くのに使います。[関数種別](../concepts/kinds.md)
- **`fn`**（`fn`）。実行時に動くチューリング完全なコード、つまりゲームシステムのための関数種別です。[関数種別](../concepts/kinds.md)
- **`.kagari` ファイル**（`.kagari` file）。`kagari build` が書き出すコンパイル済みのプログラム `game.kagari` です。[`kagari` CLI](../tools/cli.md)
- **`kagari.toml`**（`kagari.toml`）。プロジェクトのマニフェストです。[プロジェクト](../tools/projects.md)
- **`.kiarchive` ファイル**（`.kiarchive` file）。`kagari build` が `game.kagari` と同じ場所に書き出すアセットのアーカイブです。[`kagari` CLI](../tools/cli.md)
- **`.kis` / `.kix` ファイル**（`.kis` / `.kix` file）。ソースファイルです。`.kis` には言語本体だけを、`.kix` には組み込み構文も使ったコードを書きます。拡張子で決まるのは使える構文だけです。[ソースファイルとモジュール](../syntax/modules.md)
- **`Narrative` ハンドル**（`Narrative` handle）。ゲームシステムが実行中の物語に触れる唯一の手段です。台詞や選択肢の表示、入力の送信、セーブ、巻き戻しができますが、物語変数は読めません。[ゲームシステム](../concepts/system.md)
- **`pushdown fn`**（`pushdown fn`）。物語のための関数種別です。有限のデータの上で、プッシュダウン方式の制御を行います。[関数種別](../concepts/kinds.md)
- **アーム**（arm）。`choice!` の選択肢の一つ一つで、`t![…] => V` または `t![…] if cond => V` と書きます。アームが選ばれると、選択肢全体の値は `V` になります。`match` の分岐もアームと呼びます。[ステップ](../concepts/steps.md)
- **アセット**（asset）。プロジェクトのアセットディレクトリに置くファイル（画像、音声、ボイス、動画、フォント、シェーダー）です。ソースでは `asset("bg/roof.png")` のような定数で参照し、ビルド時に `.kiarchive` ファイルにまとめます。[組み込み型](../special/builtin-types.md)
- **値セマンティクス**（value semantics）。すべての型が値型であることです。代入、引数渡し、戻り値の返却では値がコピーされ、コピーを変更しても元の値は変わりません。[値、参照、クロージャ](../syntax/values.md)
- **イージング**（easing）。補間で値が変化していく速さの曲線です。[`std::screen::anim`](../../std/screen-anim.md)
- **一貫性**（consistency）。ステップで表示される画面が物語の状態だけで決まり、そのステップまでの経路には左右されないという性質です。成り立たない場合は警告 `W5004` になります。[演出](../concepts/presentation.md)
- **演出**（presentation）。プレイヤーが見たり聞いたりするものです。レンダー関数が計算し、物語の側から読み返すことはありません。[演出](../concepts/presentation.md)
- **エンティティ**（entity）。画面上のオブジェクトで、`EntityId` の定数で識別します。エンティティの生成、変更、消去はレンダーで行います。[演出](../concepts/presentation.md)
- **エンディング**（ending）。物語が終わるときに開始シーンが返す値です。終了ハンドラがこの値を受け取ります。[開始シーンとエンディング](../concepts/entry.md)
- **オーバーレイ**（overlay）。Config や Load のように、現在のモードの上に積むモードです。[ゲームシステム](../concepts/system.md)
- **カーソル**（cursor）。ステップのタイムライン上で、レンダーが次のアニメーションを予約する位置です。[`std::screen`](../../std/screen.md)
- **ガード**（guard）。選択肢のアームに付ける条件 `if cond` です。条件が成り立つ間だけ、そのアームが表示されます。[ステップ](../concepts/steps.md)
- **開始シーン**（entry scene）。`#[entry]` を付けたシーンです。ゲームシステムが物語を始められるシーンで、物語の解析の起点にもなります。[開始シーンとエンディング](../concepts/entry.md)
- **開始引数**（entry arguments）。`nav::start` が開始シーンに渡す有限型の値です。セーブに記録され、解析では取りうるすべての値を調べます。[開始シーンとエンディング](../concepts/entry.md)
- **解析キャッシュ**（analysis cache）。`kagari check` と `kagari build` が物語の解析結果を保存するファイル `<out-dir>/analysis.kagari-cache` です。ソース、コンパイラのオプション、ツールチェインが変わらない限り、解析結果を使い回します。[`kagari` CLI](../tools/cli.md#the-analysis-cache)
- **画面**（screen）。レンダーが受け取って返す `Screen` 型の値です。エンティティとそのコンポーネントからなる世界に、画面自体が持つリソースを加えたものです。[演出](../concepts/presentation.md)
- **関数種別**（kind / function kind）。`fn`、`pushdown fn`、`const fn` の三つの関数種別のどれかで、`fn` の前に書きます。関数に何ができ、何を呼べるかは種別で決まります。[関数種別](../concepts/kinds.md)
- **キーフレーム**（keyframe）。出力が入力の画面に左右されないレンダーです。つまり画面全体を宣言することになります。キーフレームかどうかはコンパイラが自分で判定します。[演出](../concepts/presentation.md)
- **食い違い**（divergence）。プログラムを変更した結果、セーブが今のプログラムに合わなくなった理由です。たとえば記録した選択肢 ID が解決できなくなった場合がこれにあたります。ロードはこれをエラーとして返します。[セーブ、再生、決定性](../concepts/saves.md)
- **クエリエンジン**（query engine）。デバッガーがゲームを動かすのに使う、ウィンドウを持たないランタイムです。物語についての問いに答えたり、物語の中を移動したりするために使います。[デバッガー](../tools/debugger.md)
- **組み込み**（builtin）。エンジンが実装し、`#[builtin]` を付けたアイテムです。組み込みのアイテムを宣言するのは標準ライブラリだけです。[組み込み型](../special/builtin-types.md)
- **組み込み構文**（form）。`name!(…)`、`name![…]`、`name!{…}` の形で書く、言語に組み込まれた決まった構文です。`s!`、`choice!`、`t!`、UI 構文があり、`.kix` ファイルでだけ使えます。[組み込み構文](../syntax/forms.md)
- **ゲームオーバーレイ**（game overlay）。Save や Backlog のように、実行中のゲームがないと使えないオーバーレイです。`Narrative` ハンドルを受け取ります。[ゲームシステム](../concepts/system.md)
- **ゲームシステム**（game system）。物語の周りにあるものすべてです。タイトル画面、メニュー、セーブ・ロード画面、設定、バックログ、ゲーム画面などを `fn` のコードで書きます。[ゲームシステム](../concepts/system.md)
- **ゲームモード**（game mode）。モードのスタックの一番下にあり、実行中の物語を持つモードです。[ゲームシステム](../concepts/system.md)
- **決定可能**（decidable）。プログラムについての問いに、どのプログラムに対してもアルゴリズムで答えを出せることです。Kagari では、物語の到達可能性は決定可能です。[設計思想：解析できるように作る](../overview/philosophy.md)
- **効果値**（effect value）。`Filter` や `Mix` のように、シェーダーとその引数を組にしたものです。画面はシェーダーをこの形で保持します。[`std::screen::shader`](../../std/screen-shader.md)
- **コンポーネント（画面）**（component, screen）。位置、不透明度、画像レイヤーなど、エンティティに付くデータです。どんなコンポーネント型があるかは標準ライブラリが決めています。[演出](../concepts/presentation.md)
- **コンポーネント（UI）**（component, UI）。UI の値を返す普通の `fn` です。そのモードを表示するときに一度だけ実行します。[ゲームシステム](../concepts/system.md)
- **再生**（replay）。記録されたトレースに沿って物語をもう一度実行することです。セーブのロードや巻き戻しに使います。[セーブ、再生、決定性](../concepts/saves.md)
- **差分**（delta）。キーフレームでないレンダーです。出力がステップ前の画面によって変わります。[演出](../concepts/presentation.md)
- **シーン**（scene）。`#[scene]` を付けた `pushdown fn` です。ステップを実行したり、他のシーンを呼び出したりできるのはシーンだけです。[シーンと即時手続き](../concepts/scenes.md)
- **シェーダー**（shader）。レンダラーが GPU で実行する WGSL ファイル（`.wgsl`）です。役割は色フィルター、合成、テクスチャー、マスク、ローカルモーション、遷移モーションの 6 種類で、そのどれか一つを持ちます。`ColorShader<A>` のようなアセット型で、役割と引数の型 `A` を表します。[`std::screen::shader`](../../std/screen-shader.md)
- **シグナル**（signal）。`fn` のコードで使うリアクティブな値です。`signal(init)` で、値を読む関数と書く関数の組として作ります。[ゲームシステム](../concepts/system.md)
- **σ**（sigma）。物語の状態です。現在位置、ローカル変数を含むコールスタック、物語変数からなります。[物語機械](../concepts/story.md)
- **システム機械**（system machine）。実行中のゲームの外側にある機械で、モードのスタックのことです。[ゲームシステム](../concepts/system.md)
- **終了ハンドラ**（exit handler）。`nav::start` に渡すクロージャです。エンディングを受け取り、ゲームが次にどこへ進むかを決めます。[開始シーンとエンディング](../concepts/entry.md)
- **種別**（kind）。関数種別を参照してください。[関数種別](../concepts/kinds.md)
- **証拠**（witness）。物語の開始地点からある位置までの経路です。セーブは、その位置に到達できることの証拠になっています。[セーブ、再生、決定性](../concepts/saves.md)
- **状態数の上限**（state cap）。解析で探索する物語の状態数の上限で、既定値は 200 000 です。上限を超えると警告 `W5006` が出ます。[プロジェクト](../tools/projects.md)
- **診断**（diagnostic）。コンパイラが出す、番号付きのエラー（`E…`）や警告（`W…`）です。[診断](../../diagnostics/index.md)
- **ステップ**（step）。物語が止まってプレイヤーの操作を待つ地点です。`s!(…)` と `choice!{…}` の 2 種類があります。[ステップ](../concepts/steps.md)
- **ステップ ID**（step ID）。ステップを識別する変わらない名前です。関数のパス、`#`、その関数内でソース順に数えたステップの番号を並べたもので、`crate::story::FirstDate#28` のようになります。既読フラグはステップ ID ごとに記録します。[ステップ](../concepts/steps.md#step-ids)
- **スナップショット**（snapshot）。σ と論理画面のコピーをキャッシュとしてトレースと一緒に保存したもので、再生をその時点から始めるために使います。*暫定：* 現在のランタイムはスナップショットを保存せず、トレースを最初から再生します。[セーブ、再生、決定性](../concepts/saves.md)
- **制作者**（studio）。ゲームを作ってリリースするチームです。[はじめに](../index.md)
- **セーブ**（save）。セーブスロットに保存した、実行中の物語の記録です。中身はトレースで、ロード時にはトレースから物語を再生します。[セーブ、再生、決定性](../concepts/saves.md)
- **設定**（setting）。プレイヤーの好みを表す永続的なグローバル値で、`Setting<T>` のハンドルとして宣言します。物語からは参照できません。[ゲームシステム](../concepts/system.md)
- **選択肢（ステップ）**（choice）。`choice!{…}` で書くステップです。アームを並べて表示し、プレイヤーが一つ選ぶのを待ちます。値は選ばれたバリアントになります。[ステップ](../concepts/steps.md)
- **選択肢 ID**（choice ID）。セーブに記録する、選択を識別する変わらない名前です。関数のパス、選択肢の `id`、バリアントからなり、`story::Prologue/confess/Confess::Yes` のようになります。[セーブ、再生、決定性](../concepts/saves.md)
- **即時手続き**（instant procedure）。`#[scene]` を付けない `pushdown fn` です。ステップを含まず、再帰もせず、ループも定数回しか回らないため、入力を待たずに必ず終わります。[シーンと即時手続き](../concepts/scenes.md)
- **属性**（attribute）。`#[scene]`、`#[entry]`、`#[must_use]` など、アイテムに付ける `#[name]` 形式の注釈です。[属性](../special/attributes.md)
- **第二級**（second-class）。`pushdown fn` の中での参照やクロージャの扱いです。引数として渡して使うことはできますが、格納、返却、キャプチャはできません。[値、参照、クロージャ](../syntax/values.md)
- **タイムライン**（timeline）。一つのステップで再生するアニメーションと音の予定表です。論理画面には含まれません。[`std::screen`](../../std/screen.md)
- **遅延参照**（deferred reference）。レンダーの中で使う設定のハンドルです。レンダーは設定の値を読めず、その設定でエンティティの表示を切り替えることしかできません。値は描画時にエンジンが反映します。[演出](../concepts/presentation.md)
- **停止性**（termination）。二つのステップの間にあるコードが必ず終わるという保証です。[シーンと即時手続き](../concepts/scenes.md)
- **定数式**（constant expression）。コンパイラがコンパイル時に値を計算する式です。[定数式](../syntax/constants.md)
- **定数評価**（const evaluation）。定数、レンダー、表化する呼び出しを求めるために、コンパイラがコンパイル時に `const fn` のコードを実行することです。実行量には決まった上限があります。[定数式](../syntax/constants.md)
- **テキスト**（text）。`t![…]` で書く `Text` 型の値で、ルビやテキスト効果を含められます。[ステップ](../concepts/steps.md)
- **テキスト効果**（text effect）。`!["…"](effect)` でテキストの一部に付ける定数の `TextEffect` です。文字色や一時停止などがあります。[ステップ](../concepts/steps.md)
- **デバッガー**（debugger）。物語を止めたり、進めたり、中身を調べたりするツールです。`kagari debug` のほか、`kagari dap` を介してエディタからも使えます。[デバッガー](../tools/debugger.md)
- **デバッグアダプター**（debug adapter）。エディタが Debug Adapter Protocol でデバッガーを操作できるようにするプログラムです。Kagari では `kagari dap` がこれにあたります。[デバッガー](../tools/debugger.md#editors)
- **デバッグビルド**（debug build）。`kagari build --profile debug` で行うビルドです。リリースビルドと同じ `game.kagari` に加え、探索済みの物語のグラフとデバッグ情報を収めた `game.kagari-cache` を、デバッグツール用に書き出します。[`kagari` CLI](../tools/cli.md#build-profiles)
- **到達可能性**（reachability）。物語の進め方しだいで、あるシーン、ステップ、状態にたどり着けるかどうかです。[設計思想：解析できるように作る](../overview/philosophy.md)
- **トランジション**（transition）。レイヤーを切り替えるときのアニメーションです。カット、クロスフェード、ルール、ワイプなどがあります。[`std::screen::anim`](../../std/screen-anim.md)
- **トレース**（trace）。セーブに保存する記録です。開始シーンとその引数、これまでのすべての選択の選択肢 ID、最後の選択より後に進んだステップ、スクリプトのハッシュ、乱数のシードからなります。[セーブ、再生、決定性](../concepts/saves.md)
- **バックログ**（backlog）。実行中の物語で表示した台詞と選択の履歴です。プレイヤーは読み返したり、その時点まで巻き戻したりできます。[ゲームシステム](../concepts/system.md)
- **非有界な画面**（unbounded screens）。あるステップで取りうる画面の種類を上限を超えて増やしてしまうレンダーです。エラー `E5005` になります。[演出](../concepts/presentation.md)
- **表化**（tabulation）。物語から呼ばれる `const fn` を、有限型の引数のあらゆる組み合わせについてコンパイル時に評価することです。これにより、どんな入力でも呼び出しが終わり、有限の結果を返すことを確かめます。[関数種別](../concepts/kinds.md)
- **描画面**（plane）。画面にあらかじめ用意された描画の層（`Background`、`Stage`、`Front`、`OverWindow`）です。エンティティは所属する描画面の中で、`z` の順に描かれます。[`std::screen`](../../std/screen.md)
- **プッシュダウンシステム**（pushdown system）。上限のないコールスタックを持つ有限状態機械です。到達可能性が決定可能で、物語はこの一種です。[設計思想：解析できるように作る](../overview/philosophy.md)
- **ブレークポイント**（breakpoint）。デバッガーが物語を止める場所です。ステップブレークポイントは物語がステップに入ったときに、命令ブレークポイントはある行のコードを実行する直前に止めます。[デバッガー](../tools/debugger.md#breakpoints)
- **プレリュード**（prelude）。すべてのモジュールに自動でインポートされる名前の集まりです。[ソースファイルとモジュール](../syntax/modules.md)
- **ヘッドレスモード**（headless mode）。ウィンドウ、音声デバイス、ゲームパッドを使わず、スクリプトの指示どおりにゲームを動かす実行方法です。[ヘッドレスモード](../tools/headless.md)
- **補間**（tween）。プロパティを元の値から新しい値へ変化させるアニメーションで、長さ、イージング、遅延を指定します。[`std::screen::anim`](../../std/screen-anim.md)
- **ホットスワップ**（hot swap）。デバッガーから、実行中のゲームを再ビルドしたゲームに差し替えることです。コードが変わったシーンは新しいコードで呼び直され、物語のそれ以外の部分は今の位置を保ちます。[デバッガー](../tools/debugger.md#hot-swap)
- **マーク**（mark）。テキストを表示していく途中に `mark(n)` で付ける名前付きの時点です。レンダーはこの時点に合わせてアニメーションを予約できます。[`std::narrative::text`](../../std/narrative-text.md)
- **メタデータ**（meta）。解放状況、既読フラグ、閲覧済みの画像など、セーブとは別に保存される永続的なグローバル状態で、`Meta<T>` のハンドルで扱います。物語からは書き込むことしかできません。[ゲームシステム](../concepts/system.md)
- **モーション**（motion）。エンティティやカメラを相対的な経路に沿って動かし、元の位置で終わるアニメーションです。[`std::screen::anim`](../../std/screen-anim.md)
- **モード**（mode）。システムのモードのスタックに積まれる一段です。ルートページ、オーバーレイ、ゲームオーバーレイ、ダイアログ、ゲームモードがあります。[ゲームシステム](../concepts/system.md)
- **物語**（story）。ゲームの `pushdown fn` の全体で、シーン、即時手続き、物語変数からなります。[物語機械](../concepts/story.md)
- **物語機械**（story machine）。ゲームモードの中で物語を実行するプッシュダウン機械です。[物語機械](../concepts/story.md)
- **物語変数**（story variable）。有限型の `static mut` です。物語を一回通して実行する間のグローバルな状態を表し、読み書きできるのは `pushdown fn` からだけです。[物語機械](../concepts/story.md)
- **有限型**（finite type）。`bool`、`Int<lo, hi>`、有限のデータだけを持つ列挙型など、取りうる値が有限個の型です。物語が実行時に保持する値は、すべて有限型です。[関数種別](../concepts/kinds.md)
- **行き詰まり選択肢**（stuck choice）。すべてのアームのガードが偽になる状態で到達できてしまう `choice!` です。エラー `E5003` になります。[ステップ](../concepts/steps.md)
- **呼び出し規則**（call rules）。どの関数種別からどの関数種別を呼べるかを定めた規則です。`fn` から `pushdown fn` は呼べず、`pushdown fn` から `fn` も呼べません。[関数種別](../concepts/kinds.md)
- **乱数の抽選**（random draw）。物語が `rng_choose` で引く値です。乱数生成器のシードはセーブに含まれ、解析では抽選で出うるすべての値を調べます。[セーブ、再生、決定性](../concepts/saves.md)
- **ランタイム**（runtime）。ビルドしたゲームを実行するプログラムです。デスクトップ版のランタイムは、ランタイムプロファイル `native_v0` を実装しています。[ランタイム](../tools/runtime.md)
- **リアクティブ**（reactive）。UI の属性や要素が、読み取っているシグナルなどのリアクティブな値が変わるたびに再評価されることです。[ゲームシステム](../concepts/system.md)
- **リサイズ**（resize）。`Natural`、`Contain(s)`、`Cover(s)` など、画像レイヤーが内容をどの大きさで表示するかの指定です。リサイズによってレイヤーの矩形が決まり、`MAIN` レイヤーの矩形がエンティティの大きさになります。[`std::screen`](../../std/screen.md#resize)
- **ルートページ**（root page）。Title、Gallery、Credits のように、実行中のゲームを持たない、スタックの一番下のモードです。[ゲームシステム](../concepts/system.md)
- **レイヤー**（layer）。エンティティが表示する画像、ラベル、動画の内容です。変更はトランジションを通してしか行えません。[演出](../concepts/presentation.md)
- **レンダー（レンダー関数）**（render, render function）。ステップの `render` 属性に渡す `const fn(Screen) -> Screen` です。ステップ前の画面から、ステップ後の画面を作ります。[演出](../concepts/presentation.md)
- **論理画面**（logical screen）。ステップのレンダーを適用した後の、画面の永続的な状態です。エンティティとそのコンポーネント、Hud、カメラ、画面フィルター、オーディオチャンネルからなります。アニメーションで論理画面が変わることはありません。[演出](../concepts/presentation.md)
