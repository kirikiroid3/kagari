関数にはそれぞれ 3 つの**種別**のどれかがあり、`fn` の前に書きます。コードにできることを言語が制限するのは、この種別だけです。

```kis
fn open_config() { nav::call(Config) }                 // Turing-complete, runtime
#[scene] pushdown fn Confession() -> Answer { … }      // the story
const fn fade_in(mut screen: Screen) -> Screen { … }   // pure, compile time
```

| 種別 | 使えるもの | 評価 |
| ---- | ---------- | ---- |
| `fn` | 物語変数以外のすべて | 実行時 |
| `pushdown fn` | 実行時は[有限型](#finite-types)のみ。物語変数も使える。ステップは `#[scene]` の中だけ | 実行時（物語の中） |
| `const fn` | すべての型。ただし物語変数、設定値、メタデータ、シグナル、I/O は使えない | 必要に応じてコンパイル時。実行時に呼ぶこともできる |

コンパイラが種別を推論することはありません。`const` と明記した関数だけが `const` になります。

## 呼び出し規則 {#call-rules}

| 呼び出し元 ↓ / 呼び出し先 → | `fn` | `pushdown fn` | `const fn` |
| --------------------------- | ---- | ------------- | ---------- |
| `fn`                | 可 | 不可（[開始シーンを始める](./entry.md)ことだけはできる） | 可 |
| `pushdown fn`       | 不可 | 可 | 可（[後述](#calling-const-fn-from-the-story)） |
| `const fn`          | 不可 | 不可 | 可 |

この表に反する呼び出しはエラー `E3001` になります。物語の中ではさらに[シーンと即時手続き](./scenes.md#scenes-and-instant-procedures)を区別する規則があり、ステップの実行（`E3002`）、別のシーンの呼び出し（`E3003`）、乱数の取得（`E3024`）は `#[scene]` でしか行えません。

関数ポインタやクロージャの型にも種別が含まれるので、これらを経由しても規則は崩れません。`pushdown fn() -> R` 型の値が指せるのは `pushdown fn` だけです。したがって、物語がポインタ経由でチューリング完全なコードを呼ぶことはできません（[値、参照、クロージャ](../syntax/values.md)を参照）。

種別ごとにまとめると次のとおりです。

| 種別 | 呼べるもの | 実行時に保持できるもの | ステップ | 物語変数 |
| ---- | ---------- | ---------------------- | -------- | -------- |
| `fn` | `fn`、`const fn`。開始シーンを始められる | 何でも | 不可 | 不可 |
| `#[scene] pushdown fn` | シーン、即時手続き、`const fn`（引数が定数か有限型の場合） | 有限型 | 可 | 読み書き可 |
| `pushdown fn`（即時手続き） | 即時手続き、`const fn`。再帰は不可、ループは `for` のみ | 有限型 | 不可 | 読み書き可 |
| `const fn` | `const fn` | 何でも | 不可 | 不可 |

## `pushdown fn` {#pushdown-fn}

`pushdown fn` は物語の一部で、次のことができます。

- [有限型](#finite-types)の値だけを受け取り、保持し、返す（違反すると `E3008`）。
- [物語変数](./story.md#story-variables)を読み書きする。
- ほかの `pushdown fn` や `const fn` を呼ぶ。

`#[scene]` を付けた `pushdown fn` を**シーン**と呼びます。[ステップ](./steps.md)を実行できるのはシーンだけで、ステップはプレイヤーが入力するまで物語を止めます。ほかのシーン（自分自身も含む）を呼べるのもシーンだけです。シーン内のループや呼び出しの循環は、必ずどこかでステップを通らなければなりません（[停止性](./scenes.md#termination)を参照）。`#[scene]` のない `pushdown fn` は**即時手続き**です。ステップを実行せず、再帰もせず、ループは有界なものだけなので、入力を待たずに必ず終わります。どちらの場合も、ある入力から次の入力までのコードは必ず終わります。

シーン同士は Kotlin の `suspend` 関数のように直接呼び合い、`.await` は不要です。呼び出しの奥のどこかでステップに達すると物語全体が止まり、入力があるとその地点から再開します。

## `const fn` {#const-fn}

`const fn` は純粋かつ決定的な関数で、結果は引数だけで決まります。物語変数（`E3007`）、設定値、メタデータ（`E3013`）、シグナルは読めず、I/O もできません。一方で中身はチューリング完全で、ループ、再帰、Rust の整数、`Rat`、`Decimal`、`String`、`Vec` を自由に使えます。

定数、[レンダー関数](./presentation.md)、物語からの呼び出しのように、コンパイル時に結果が必要な場面では、コンパイラが `const fn` を評価します。評価には 1,000,000 評価ステップという固定の上限があり（*暫定*：コンパイラの設定項目になる可能性があります）、上限を超えると、その値を必要とした呼び出し箇所でエラー `E4003` になります。実行時に `fn` のコードから呼んだ `const fn` は、通常の関数呼び出しと同じです。

### 物語から `const fn` を呼ぶ {#calling-const-fn-from-the-story}

`pushdown fn` から `const fn` を呼べるのは、引数がすべて[定数式](../syntax/constants.md)か有限型の場合です。

- **引数がすべて定数の場合。** コンパイラはコンパイル時に呼び出しを評価し、結果の値で置き換えます（**畳み込み**）。値の型は問いません。`fade(ms(500))` がその例です。
- **有限型の実行時の値を含む場合。** コンパイラは関数を**表化**します。呼び出しが受け取りうる引数の組み合わせすべてについて関数を評価し、どの入力でもエラーなく終わって有限の結果を返すことをコンパイル時に証明します。プレイ中は、実際の引数で普通に関数を呼びます。結果は有限型でなければなりません（`E3008`）。引数の組み合わせが 65,536 を超えるとエラー `E4004` になります（*暫定*：コンパイラの設定項目になる可能性があります）。

```kix
const fn mood(affection: Int<0, 5>, met: bool) -> Mood {
    match (affection, met) {
        (4..=5, true) => Mood::Warm,
        (_, true) => Mood::Polite,
        _ => Mood::Stranger,
    }
}

#[scene]
pushdown fn Greeting() {
    match mood(AFFECTION_MIO, MET_MIO) {   // tabulated: 6 × 2 entries
        Mood::Warm => s!(t!["\"There you are!\""]),
        Mood::Polite => s!(t!["\"Hello.\""]),
        Mood::Stranger => s!(t!["\"…Who are you?\""]),
    }
}
```

書き手としては、物語の補助ロジックを、`bool`、列挙型、`Int<lo, hi>` のような小さな有限型を引数に取る普通の `const fn` として書けば十分です。関数内のエラー（オーバーフロー、ゼロ除算、終わらないループ）は、それを起こす引数の値とともにコンパイル時に報告されます。プレイ中に起きることはありません。

## `fn` {#fn}

普通の `fn` はチューリング完全な実行時のコードで、ゲームシステム、その UI、セーブ、設定、メタデータを担当します。`pushdown fn` は呼べず、物語変数も読めません。物語に入る方法は[開始シーンを始める](./entry.md)ことだけで、実行中の物語に触れる手段は [`Narrative` ハンドル](./system.md)だけです。

## 有限型 {#finite-types}

`pushdown fn` のローカル変数、引数、戻り値、物語変数の型は、すべて有限でなければなりません。型が有限であるとは、値の数が有限で、コンパイラがそれを列挙できるということです。

| 有限 | 有限でない |
| ---- | ---------- |
| `bool`、`()`、`!` | Rust の整数（`u8`、`i32` など）、`Rat`、`Decimal` |
| `Int<lo, hi>` | `String`、`Vec<T>` |
| 有限なデータだけを持つヴァリアントからなる列挙型 | `Screen` などの組み込みのハンドル型 |
| 有限型からなる構造体、タプル、配列 `[T; N]` | 第一級のクロージャ |
| 有限な `T` の `Option<T>` | シグナル、設定値、メタデータの値 |
| `Text`（値はプログラム中の定数テキスト） | 自分自身を含む型（再帰型） |
| ファイルのアセット型 `ImageAsset`、`AudioAsset`、`VoiceAsset`、`VideoAsset`、`FontAsset`（値はプログラム中のアセット定数） | `EntityId`、`Part`、`Mark`、`Duration`、`Color`（Rust の整数を含むため）。`ColorShader<A>` などのシェーダー型 |
| `pushdown fn`、`scene fn`、`const fn` のポインタ（値はプログラム中の名前付き関数） | |
| 有限な `T` の `&T`、`&mut T`（引数として） | |

定数式はコンパイル時に畳み込まれるので、どの型であっても `pushdown fn` の中に書けます。標準ライブラリの型の一覧は、標準ライブラリのリファレンスの[標準ライブラリに関するコンパイラの規則](../../std/appendix/rules.md)にあります。

## なぜこれで成り立つのか {#why-this-works}

エンジンが物語に求める性質は 2 つです。どのステップも必ず終わること、そして「`MET_B` が false のままこのステップに到達できるか」といった問いにコンパイラが答えられることです。有限なデータ上のプッシュダウンシステムならどちらも成り立ち、種別によって物語はまさにその形になります。

- **物語は閉じている。** `pushdown fn` が呼べるのは `pushdown fn` と `const fn` だけです。物語から呼んだ `const fn` は定数に畳み込まれるか表化され、受け取りうるどの入力でも有限の結果を返して終わることが証明されます。
- **入口は開始シーンだけ。** チューリング完全なコードが物語に入れるのは、開始シーンを始めるときだけです。その引数は有限で、セーブに記録され、解析はそのすべての値について成り立ちます。外に返ってくるのは開始シーンの戻り値と、物語が書き込むだけで読まないメタデータだけです。
- **フレームは有限のまま。** スタックフレームが保持するのは戻り先と有限なローカル変数だけです。物語の中の参照とクロージャは第二級なので、状態の一部にはなりません。
- **関数ポインタも有限。** 名前付き関数は有限個しかないので、ポインタの値は有限集合に収まります。

そのため、ゲームシステムや演出では自由に計算できます。物語の解析はそれらに依存しません。背景は[設計思想：解析できるように作る](../overview/philosophy.md)を参照してください。
