## 開始シーン {#entry-scenes}

```kix
enum Ending { NormalEnd, AzusaEnd }

#[scene]
#[entry]
pushdown fn Main(cleared_azusa: bool) -> Ending {
    …
    if ROUTE == Route::Azusa {
        return Ending::AzusaEnd;
    }
    Ending::NormalEnd
}
```

**開始シーン**とは、`#[entry]` も付けたシーンのことです。ゲームシステムが物語を始められる場所であり、チューリング完全なコードから物語に入る唯一の入口です。

- ゲームには開始シーンが少なくとも 1 つあります。追加の章、アフターストーリー、シーン回想などは、それぞれ別の開始シーンになります。
- 引数と戻り値の型は有限型でなければならず（`E3008`）、`Text` を含めることもできません（`E3009`）。`fn` のコードは実行時にテキストを組み立てられるので、ゲームシステムから渡された `Text` がプログラム中の定数テキストである保証がないためです。
- `#[scene]` なしで `#[entry]` を付けるとエラー `E3018` になります。それ以外の点では開始シーンも普通のシーンで、ほかのシーンから呼ぶこともできます。
- 物語の解析はすべて開始シーンを起点にします。どの開始シーンからも到達できないシーンやステップは報告されます（`W5008`、`W5009`）。

## 物語の開始 {#starting-the-story}

ゲームシステムは、`fn` のコードから `nav::start` を呼んで物語を始めます。

```kix
button!{on_click = || nav::start(story::Main, (CLEARED_AZUSA.get(),), on_ending), t!["Start"]}

fn on_ending(ending: story::Ending) {
    match ending {
        story::Ending::AzusaEnd => { CLEARED_AZUSA.set(true); nav::goto(Credits) }
        story::Ending::NormalEnd => nav::goto(Credits),
    }
}
```

`nav::start` には、開始シーン、その引数、終了時のハンドラを渡します。物語に入る方法はこれしかありません。

- `story::Main` は `#[entry]` シーンを指す `scene fn(P1, …, Pn) -> R` 型のポインタです。引数はタプル `(P1, …, Pn)` で、終了時のハンドラは `Fn(R)` です。型が合わないとエラー `E2027` になります。
- 引数の型は開始シーンの有限な引数の型で、値はセーブに記録されます。

ゲームシステム側の説明は、[ゲームシステム](./system.md)と、標準ライブラリのリファレンスの [`std::system::nav`](../../std/system-nav.md) にあります。

## 開始引数 {#arguments}

開始引数を使うと、以前のプレイでクリアしたエンディングのように、プレイをまたいで残る状態を物語から読めます。ゲームシステムがメタデータを読み、物語を始めるときにその値を渡します。開始引数はトレースと一緒にセーブに保存されるので、後でメタデータが変わっていても、ロード時には同じ値で再生されます。コンパイラは開始引数をどんな値も取りうるものとして扱い、すべての解析は引数のどの値についても成り立ちます。

## エンディング {#the-ending}

開始シーンが戻ると物語は終わり、制御はゲームシステムに戻ります。戻り値でどのエンディングに到達したかを伝え、次に何をするか（スタッフロールを流す、タイトルに戻るなど）は終了時のハンドラが決めます。受け渡されるのは戻り値だけで、ゲームシステムから物語変数は見えません。ハンドラがどこにも遷移しなければ、モードスタックは最初のページにリセットされます。

`Main` はどの経路でも `Ending` を返さなければならないので、エンディングを返し忘れた経路は型エラーになります。また、終了時のハンドラは網羅的な `match` なので、ゲームシステムが処理していないエンディングがあればコンパイルエラーになります。

## メタデータの書き込み {#writing-meta}

```kix
CLEARED_AZUSA.write(true);
```

物語からメタデータに書き込むには、`Meta<T>` の `pushdown fn` メソッドである `write` を使います。

| メソッド | 種別 | 用途 |
| -------- | ---- | ---- |
| `get()` | `fn` | ゲームシステムのコードが読む |
| `set(v)` | `fn` | ゲームシステムのコードが書く |
| `write(v)` | `pushdown fn` | 物語が書く。物語から読み返すことはできない |

物語にとってメタデータは**書き込み専用**です。読めるのは `fn` だけで、`const fn` のコードではメタデータを参照することすらできません（`E3013`）。物語が読み返せない書き込みは物語の制御フローに影響しないので、物語の解析はどれも影響を受けません。書き込みはロードや巻き戻しでも元に戻らず、一度解放したものは解放されたままです。メタデータが物語に届くのは、開始時の開始引数を通してだけです。

おまけ画面からのシーン**回想**は、別の `#[entry]` シーンを `nav::start` で始めるだけです。回想は、物語がそのシーンを初めて通ったときに書き込む `Meta<bool>` で解放します。
