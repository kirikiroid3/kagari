---
title: "ヘッドレスモード"
---

ヘッドレスモードでは、ウィンドウ、音声デバイス、ゲームパッドを使わずにゲームを動かします。入力と時計の進み方はスクリプトで指示し、スクリーンショットもスクリプトから書き出します。CI でのスモークテスト、あるルートがエンディングまでたどり着くかの確認、ビルド間でのスクリーンショット比較など、自動テストに使います。

## ヘッドレスでの実行 {#running-headless}

```text
kagari-desktop-runtime [GAME_DIR] --headless --script <FILE> --out <DIR> [--seed <N>] [--data-dir <DIR>]
```

| オプション | 意味 |
| ---------- | ---- |
| `--headless` | ウィンドウを開かずに実行します。`--script` と `--out` も必要です。 |
| `--script <FILE>` | 入力スクリプト（後述）。 |
| `--out <DIR>` | 出力ディレクトリ。なければ作成します。キャプチャはここに書き出します。 |
| `--seed <N>` | 新しく始まる物語すべてに使う乱数シード。既定は `1`。 |
| `--data-dir <DIR>` | 設定とセーブを保存するディレクトリ。既定は `<out>/data`。 |

`--script`、`--out`、`--seed` を `--headless` なしで指定すると、使い方の誤り（ステータス 2）になります。`GAME_DIR` の扱いは[ランタイム](./runtime.md#command-line)と同じです。

ヘッドレスモードでも描画には GPU を使うので、GPU ドライバーは必要です。ディスプレイサーバーは要りません。ハードウェアの GPU がない環境（CI のマシンによくあります）でも、Mesa の llvmpipe のようなソフトウェアのアダプターで動きます。

## 決定性 {#determinism}

ヘッドレスでの実行には再現性があります。ゲーム、スクリプト、シードが同じなら、同じキャプチャが得られます。

| 項目 | ウィンドウあり | ヘッドレス |
| ---- | -------------- | ---------- |
| 時計 | 実時間 | 0 ms から始まり、`wait` のときだけ進む |
| セーブ時刻（`local_time`） | ローカル時刻 | 常に 2026-01-01 00:00:00 |
| 新しい物語のシード | システム時計とプロセス ID から決める | `--seed`（既定は `1`） |
| 設定とセーブ | OS ごとのデータディレクトリ | `--data-dir`（既定は `<out>/data`） |
| 音声 | 再生する | 処理はするが再生しない |
| ムービー | 再生に合わせてデコード（可能ならハードウェアで） | キャプチャのたびに、その時刻ちょうどのフレームをソフトウェアでデコード |
| ゲームパッド | 読み取る | なし |

設定とセーブは、実行が終わってもデータディレクトリに残ります。毎回まっさらな状態から始めたい場合は、データディレクトリを削除するか、新しい `--out` を指定してください。

## スクリプトの形式 {#script-format}

スクリプトは、1 行に 1 コマンドを書くテキストファイルです。引数は空白で区切ります。空行と、空白以外の最初の文字が `#` の行は読み飛ばします。コマンドは上から順に実行します。

| コマンド | 動作 |
| -------- | ---- |
| `wait MS` | 時計を `MS` ミリ秒進めます。一度に最大 16 ms ずつ進め、そのたびにゲームを更新します。 |
| `key KEY` | キーを押して離します。 |
| `down KEY` | キーを押したままにします。 |
| `up KEY` | キーを離します。 |
| `click X Y` | マウスをデザイン解像度上の座標（`X`, `Y`）に動かし、左ボタンを押して離します。 |
| `move X Y` | マウスをデザイン解像度上の座標（`X`, `Y`）に動かします。 |
| `wheel DY` | ホイールを `DY` ノッチ回します。`DY > 0` で上にスクロールします。 |
| `capture NAME` | 現在のフレームを `<out>/NAME.png` に書き出し、`wrote <path>` と表示します。`NAME` は `A-Z a-z 0-9 _ -` だけからなる 1〜64 文字です。 |
| `expect-crash` | この時点で、ゲームがエラーで停止していなければなりません。 |
| `assert-no-crash` | この時点で、ゲームがまだ動いていなければなりません。 |

- `KEY` には `std::system::Key` のバリアント名を書きます。`Enter`、`Escape`、`Space`、`Backspace`、`Tab`、`Up`、`Down`、`Left`、`Right`、`PageUp`、`PageDown`、`Home`、`End`、`Shift`、`Control`、`Alt`、`F1`〜`F12`、`A`〜`Z`、`Digit0`〜`Digit9` です。大文字と小文字は区別します。
- 座標とホイールの回転量は 10 進数（`285`、`12.5`）で書きます。座標はゲームのデザイン解像度で表し、ウィンドウの大きさとは関係ありません。
- 入力コマンド（`key`、`down`、`up`、`click`、`move`、`wheel`）では時計は進まず、ゲームはその時点の時刻で入力を処理します。アニメーションやテキストを進めたいときは `wait` を入れてください。
- キャプチャはデザイン解像度の PNG ファイルです。

スクリプトは、ゲームを開始する前に全体を解析します。構文に誤りがあると、`script:<line>: <message>` の形のメッセージ（例：`` script:3: unknown key `space` ``）を出してステータス 5 で終了します。

### エラーとクラッシュ {#errors-and-crashes}

ゲームがエラーで停止した場合（[ゲームがエラーで停止したとき](./runtime.md#when-the-game-stops-with-an-error)を参照）の扱いは次のとおりです。

- `expect-crash` がなければ、次に `capture` 以外のコマンドが来た時点でステータス 3 で終了します。最後のコマンドの実行中にエラーが起きた場合も、ステータス 3 で終了します。
- `expect-crash` があれば、エラーは想定どおりとして扱います。それ以降の `capture` 以外のコマンドはすべて無視し、ステータス 0 で終わります。`capture` はエラー画面を書き出します。
- ゲームがまだ動いているのに `expect-crash` が来ると、スクリプトのエラー（ステータス 5）になります。
- エラーの後に `assert-no-crash` が来ると、ステータス 3 で終了します。

ゲームが自分で終了した場合（「終了」ボタンを押したときなど）は、残りのコマンドを飛ばしてステータス 0 で終わります。スクリプトの最後に達してもゲームが動いていれば、プレイヤーがウィンドウを閉じたときと同じようにゲームを終了させます。

## 終了ステータス {#exit-statuses}

| ステータス | 意味 |
| ---------: | ---- |
| 0 | スクリプトを最後まで実行した（またはゲームが終了した）。 |
| 2 | 使い方の誤り、`game.kagari` がない、またはゲームを開始できない（`.kagari` ファイルが不正、このランタイムにない組み込みのアイテムをインポートしている、フォントを読み込めない。[ランタイム](./runtime.md#when-the-game-stops-with-an-error)を参照）。 |
| 3 | スクリプトが想定していないエラーでゲームが停止した、または `assert-no-crash` が失敗した。 |
| 4 | GPU の障害。使えるアダプターがない、メモリが足りない、デバイスが失われた。 |
| 5 | スクリプトのエラー。スクリプトを読み込めない・解析できない、`expect-crash` の時点でゲームが動いている、`--out` を作成できない、キャプチャを書き出せない。 |

Windows の `cmd` と PowerShell は、そう指示しない限りランタイムの終了を待ちません。[Windows のターミナルから実行する](./runtime.md#running-from-a-terminal-on-windows)を参照してください。

## 例 {#example}

`example/test_game1` のスモークテストの例です。タイトル画面が出るまで待ってキャプチャし、タイトルの Start ボタンをクリックしてから、最初の台詞をキャプチャします。

```sh
cat > smoke.txt <<'EOF'
wait 2000
capture title
# the title's Start button
click 285 265
wait 1000
capture first-line
assert-no-crash
EOF
kagari-desktop-runtime example/test_game1/target/v0 --headless --script smoke.txt --out shots --seed 1
```

`shots/title.png` と `shots/first-line.png` を書き出し、設定とセーブは `shots/data` に保存します。最後の時点でゲームがまだ動いていれば、終了ステータスは 0 です。
