Kagari には、エディタと連携するための 4 つの部品が付属しています。

| 部品 | 機能 | 場所 |
| ---- | ---- | ---- |
| 言語サーバー | 診断、整形、定義へのジャンプ、ホバー、アウトライン表示 | `kagari lsp` |
| デバッグアダプター | ブレークポイント、ステップ実行、物語のコールスタックと変数の表示、デバッガーのコマンド | `kagari dap` |
| tree-sitter 文法 | `.kis` と `.kix` の構文ハイライトと構造解析 | `tooling/tree-sitter-kagari` |
| Zed 拡張機能 | 上記すべてを、Zed にそのまま導入できる形にまとめたもの | `tooling/zed-kagari` |

どれを使う場合も `kagari` の実行ファイルが必要です。[インストール](./cli.md#installing)を参照してください。

## 言語サーバー {#the-language-server}

`kagari lsp` は言語サーバーを起動します。通信には標準入出力上の Language Server Protocol を使います。拡張子が `.kis` と `.kix` のファイルに対して、`kagari` コマンドを引数 `lsp` で起動するようエディタを設定してください。

### 機能 {#features}

| 機能 | LSP リクエスト | 備考 |
| ---- | -------------- | ---- |
| 診断 | `textDocument/publishDiagnostics` | `kagari check` と同じ診断を、開いていないファイルも含め、プロジェクト内のすべてのファイルについて報告。編集するたびにバックグラウンドで計算し直します。 |
| 整形 | `textDocument/formatting` | `kagari fmt` と同じ結果になります。構文エラーのあるファイルは変更しません。 |
| 定義へのジャンプ | `textDocument/definition` | パス、ローカル束縛、メソッド呼び出しから定義へジャンプできます。標準ライブラリの宣言にもジャンプできます（後述）。フィールドアクセスと `use` のパスからはジャンプできません。 |
| ホバー | `textDocument/hover` | カーソル位置にあるもののヘッダー（シグネチャ）または型と、`///` のドキュメントコメントを表示。 |
| ドキュメントシンボル | `textDocument/documentSymbol` | ファイル内のアイテムを、書かれたとおりの入れ子構造で、列挙型のバリアントも含めて返します。エディタではアウトラインとして表示されます。 |

上記以外のリクエストには対応していません。サーバーはドキュメント全体を同期するので、保存前の編集内容も反映されます。

### 言語サーバーでのプロジェクトの扱い {#projects-in-the-language-server}

サーバーは、ルートに `kagari.toml` があるワークスペースフォルダごとにプロジェクトを読み込みます。さらに、ファイルを開くたびに、そのファイルのディレクトリから親ディレクトリへさかのぼって `kagari.toml` を探し、見つかったプロジェクトも読み込みます。ファイルを含むプロジェクトが複数ある場合は、ルートが最も深いプロジェクトの一部として検査します。`kagari check` と同じく、マニフェストの[コンパイラオプション](./projects.md#compiler-options)が適用されます。

どのプロジェクトにも属さないファイルについては、構文の診断だけを報告します。`kagari.toml` が不正な場合や、別のバージョンのツールチェインを要求している場合は、そのエラーをエディタ上にメッセージとして表示します。

エディタがファイルの監視に対応していれば、サーバーは `.kis`/`.kix` ファイル、`kagari.toml`、アセットディレクトリ内でのファイルの作成と削除を監視します。そのため、アセットファイルを追加したり削除したりすると、診断も更新されます。`kagari.toml` を変更すると、プロジェクトを読み込み直します。

標準ライブラリのソースはコンパイラに組み込まれています。定義へのジャンプで開けるように、サーバーはシステムの一時ディレクトリ内の `kagari-std-<version>` にそのコピーを書き出します。このコピーを編集しても何の効果もありません。

## フォーマッタ {#the-formatter}

`kagari fmt` と言語サーバーの整形機能は、同じフォーマッタを使っています。rustfmt に近いスタイルで、設定項目はありません。

- できる限り 1 行が **100 桁**に収まるように折り返します。幅は表示上の幅で数えるので、全角文字は 2 桁になります。
- インデントは 1 段あたり **スペース 4 つ**です。
- 引数リスト、組み込み構文、メソッドチェーン、ブロックといったまとまりは、1 行に収まればそのまま 1 行に書き、収まらなければ要素ごとに改行します。それに合わせて、リストのカンマを付けたり外したりします。
- コメントはすべて残し、対応するコードから離しません。コードと同じ行の後ろに書いたコメントはその行末に、それ以外のコメントは次のトークンの前に置かれます。
- 連続する空行は 1 行にまとめます。行末の空白は取り除きます。ファイルの末尾は改行 1 つで終わります（空のファイルは空のままです）。
- 組み込み構文（`s!`、`choice!`、`t![…]`、UI 構文）の中も整形します。

構文エラーのあるファイルは整形しません。フォーマッタは整形後の出力をもう一度パースし、トークンとコメントが入力と一致することを確かめます。一致しなければフォーマッタのバグなので、エラーを出して整形を中止し、ファイルは変更しません。

コマンドラインのフラグについては [`kagari fmt`](./cli.md#kagari-fmt) を参照してください。

## Zed {#zed}

`tooling/zed-kagari` にある Zed 拡張機能は、`.kis` と `.kix` ファイルを `Kagari` 言語として扱えるようにします。tree-sitter 文法にもとづくハイライト、アウトライン、インデントと括弧の規則に加え、言語サーバーも使えます。

インストール手順は次のとおりです。

1. `kagari` をインストールし、`PATH` から実行できるようにします（[Kagari のインストール](../../tutorial/install.md)を参照）。
2. Zed でコマンド **zed: install dev extension** を実行し、Kagari リポジトリの `tooling/zed-kagari` ディレクトリを選びます。

拡張機能は `kagari lsp` を起動します。別の実行ファイルや引数を使いたい場合は、Zed の `settings.json` で指定します。

```json
{
  "lsp": {
    "kagari": {
      "binary": {
        "path": "/path/to/kagari",
        "arguments": ["lsp"]
      }
    }
  }
}
```

`kagari` の場所が設定されておらず、`PATH` にも見つからない場合、Zed は `` `kagari` was not found on PATH `` と報告します。

### Zed でのデバッグ {#debugging-in-zed}

この拡張機能は、デバッグアダプター `Kagari` も登録します。このアダプターはワークツリーで `kagari dap` を実行します（設定項目の一覧は[デバッガー](./debugger.md#editors)を参照）。デバッグシナリオは `.zed/debug.json` に追加します。

```json
[
  {
    "label": "Kagari: run in a window",
    "adapter": "Kagari",
    "request": "launch",
    "mode": "window",
    "stopOnEntry": true,
    "watch": true
  },
  {
    "label": "Kagari: query engine",
    "adapter": "Kagari",
    "request": "launch",
    "mode": "headless",
    "seed": 1
  },
  {
    "label": "Kagari: attach",
    "adapter": "Kagari",
    "request": "attach",
    "port": 4711
  }
]
```

launch の場合は、まずデバッグプロファイルでビルドします（`"buildFirst": false` でビルドを省略できます）。ブレークポイントは行をクリックして設定します。`s!(…)` や `choice!{…}` のある行では、物語がそのステップに入ったときに止まります。物語のコードのそれ以外の行では、その行のコードを実行する前に止まります。デバッグコンソールでは、`ls` や `nav crate::story::Ending#0` などデバッガーのコマンドを使えます。`"watch": true` にすると、ソースファイルを保存するたびにゲームを再ビルドし、実行中のセッションに[ホットスワップ](./debugger.md#hot-swap)します。デバッグコンソールで `swap` を実行すれば、同じことを好きなときに行えます。

## その他のエディタ {#other-editors}

LSP クライアントを備えたエディタであれば、言語サーバーを利用できます。拡張子 `kis` と `kix` に対して、コマンド `kagari lsp` を登録してください。Debug Adapter Protocol のクライアントを備えたエディタであれば、デバッグアダプターも利用できます。[デバッガー](./debugger.md#editors)にある launch と attach の設定を使い、`kagari dap` を標準入出力で起動してください。

構文ハイライトには、`tooling/tree-sitter-kagari` にある tree-sitter 文法（`grammar.js` と、`src/` 内の生成済みパーサー）を使います。スコープは `source.kagari` で、`.kis` と `.kix` のどちらのファイルにも対応しています。この文法用のハイライト、アウトライン、インデント、括弧のクエリは `tooling/zed-kagari/languages/kagari/` にあります（`highlights.scm`、`outline.scm`、`indents.scm`、`brackets.scm`）。Neovim や Helix などのエディタでも、キャプチャ名をそのエディタの流儀に合わせて調整すれば再利用できます。
