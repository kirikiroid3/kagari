---
title: "デバッガー"
---

物語デバッガーを使うと、手でプレイしなくても物語の中を自由に移動し、物語について調べられます。物語がいまどこにいるか、次に何が来るか、あるステップにここからまだ到達できるか、どの選択肢（と乱数の抽選結果）でそこへ行けるか、といったことです。デバッガーは、ウィンドウを開かずにゲームを動かす**クエリエンジン**の上でも、**ウィンドウで実行中**のゲームの上でも使えます。ウィンドウの場合は、移動するたびに新しい状態がすぐ画面に反映されます。エディタからはどちらにも Debug Adapter Protocol で接続します。設計については開発者ガイドの [The Debugger](https://github.com/kirikiroid3/kagari/blob/main/docs/dev/src/runtime/debugger.md) を参照してください。

## デバッグビルド {#debug-builds}

デバッガーは、`kagari build --profile debug` が `game.kagari` と同じ場所に書き出すデバッグ用の成果物 `game.kagari-cache` を読み込みます（[ビルドプロファイル](./cli.md#build-profiles)を参照）。中身は、`nav` に必要な探索済みの物語グラフと、ローカル変数の名前です。このファイルがなくてもほかのコマンドは使えますが、変数名は `arg0`、`arg1`、… になります。別のビルドで作られたデバッグ用成果物は無視します。`kagari debug` と `kagari dap` は、ゲームを起動する前に自分でデバッグプロファイルのビルドを行います。

## 位置 {#positions}

位置は**ステップ ID** で表します（`crate::story::Start#3` のように、関数のパス、`#`、関数内でのステップ番号を並べたもの。[ステップ ID](../concepts/steps.md#step-ids) を参照）。選択肢の**アーム**は、セーブに記録されるのと同じアーム ID で指定します。アーム ID は、アームの値のバリアントパス（`crate::Pick::B`）か、`#` とアーム一覧での番号です。表示中のアームを一つに特定できるなら、アーム ID の末尾の部分（`B`、`Pick::B`）だけでも受け付けます。

デバッガーは、セーブをロードするときと同じ方法で物語を動かします。つまり、開始シーンから選択肢を再生します（[セーブ、再生、決定性](../concepts/saves.md)）。再生中は何も保存せず、音も鳴らしません。既読フラグも、メタデータの書き込みも、オートセーブも、音声もありません。移動が終わると、物語はたどり着いた場所で**停止**します。先へ進めるには `continue` を使います。

## `kagari debug` {#kagari-debug}

```text
kagari debug [--manifest-path <PATH>] [--target <TARGET>] [--entry <PATH>] [--seed <N>] [--no-build] [--watch]
kagari debug --window [--runtime <PATH>] [--manifest-path <PATH>] [--target <TARGET>] [--no-build] [--watch]
kagari debug --attach <ADDRESS> [--manifest-path <PATH>] [--target <TARGET>] [--watch]
```

`kagari debug` はプロジェクトをデバッグプロファイルでビルドしてゲームを起動し、コマンドを 1 行ずつ読み込みます。既定ではクエリエンジンで動かします。物語は、物語グラフの先頭にある開始シーン（`--entry` があればそのシーン）から、グラフに記録された引数とシード `--seed`（既定は `1`）で始まり、最初のステップで停止します。

| オプション | 意味 |
| ---------- | ---- |
| `--manifest-path <PATH>` | プロジェクトの `kagari.toml`。既定では最も近いもの。 |
| `--target <TARGET>` | デバッグするターゲット。既定では `build.targets` の最初のもの。 |
| `--entry <PATH>` | クエリエンジンで開始する開始シーン（クエリエンジン専用）。 |
| `--seed <N>` | クエリエンジンの乱数シード。既定は `1`。 |
| `--window` | クエリエンジンの代わりに、ゲームをウィンドウで起動します（`kagari-desktop-runtime` を、`kagari` と同じ場所か `PATH` から探します）。ゲームのログ（標準エラー出力）はプロンプトの上に表示します。コマンドをパイプで渡したときは標準エラー出力に出します。 |
| `--runtime <PATH>` | `--window` で起動するランタイム。 |
| `--attach <ADDRESS>` | `--debug-port` 付きで起動したゲームに接続します。`PORT` か `HOST:PORT` で指定します。ビルドは行いません。 |
| `--no-build` | 事前のビルドを省き、ターゲットディレクトリにあるファイルをそのまま使います。 |
| `--watch` | プロジェクトのファイルを約 0.5 秒ごとに監視します。変更を見つけると `source changed: rebuilding` と表示し、`swap` と同じ処理を行います。 |

場所は `file:line:column` の形で表示します。ファイルはプロジェクトのルートファイルがあるディレクトリからの相対パスです。コマンドはパイプで渡すこともでき（`kagari debug < commands.txt`）、デバッガーは順に答えて、入力が終わると終了します。

端末ではコマンド行を編集できます。← と → で行の中を移動し、↑ で入力済みの文字列から始まる以前のコマンドを新しい順に表示し、↓ で戻ります（最も新しいものを過ぎると入力した文字列に戻ります）。Ctrl-R で以前のコマンドを検索し、Ctrl-C で行を破棄し、Ctrl-D でセッションを終えます。コマンドはデバッガーが終了するまで記憶されます。コマンドの入力中に届いた出力（ウィンドウでの停止、`--watch` の再ビルド）はプロンプトの上に表示します。プロンプトの表示中にゲームがなくなると、デバッガーは Enter を押したあとに終了します。

## コマンド {#commands}

| コマンド | 効果 |
| -------- | ---- |
| `stack` | 開始シーンから現在のステップまでのコールスタック。内側から順に、各シーンの引数と、そのシーンがいるステップ（または呼び出し位置）を表示します。 |
| `ls [-h N \| --head N] [-t N \| --tail N]` | 現在のステップから次の選択肢までの全ステップを 1 行ずつ表示します。内容はステップ ID、話者、テキストの冒頭です。`-h` は先頭の `N` 個、`-t` は末尾の `N` 個だけを残します。 |
| `goto <step>` | 直前の選択肢から次の選択肢まで（両端を含む）の範囲にあるステップへ移動します。範囲外を指定するとエラーになり、その二つの選択肢を表示します。 |
| `push <arm>...` | 次の選択肢で 1 番目のアームを選び、その次の選択肢で 2 番目のアームを選ぶ、という操作を続けます。最後のアームを選んだ直後で停止します。指定したアームがない選択肢に当たるとそこで止まり、その選択肢にあるアームを挙げたエラーになります。 |
| `pop` | 直前の選択肢の、アームを選ぶ前の状態に戻ります。`pop` するたびに一つ前の選択肢へさかのぼります。 |
| `detail [<step>]` | ステップの詳しい情報（既定は現在のステップ。ほかのステップを指定する場合は、直前の選択肢と次の選択肢の間にあるものに限ります）。話者、ルビと効果を含むテキスト、ボイス、レンダーとそれがキーフレームかどうかを表示します。選択肢なら、その `id` と、全アームのアーム ID、テキスト、表示されるかどうかを表示します。 |
| `nav <step> [--seeds N]` | 現在の状態からそのステップに到達できるか、どうすれば到達できるか（後述）。 |
| `seed [<n>]` | 乱数シードを表示します。`n` を指定すると、現在の位置までをシード `n` で再生し直します（選択肢が合わなくなるとエラー）。 |
| `scenario` | ゲームのすべてのシーンを、パスの順に、それぞれのステップ数と一緒に表示します。コード内で停止しているときにも使えます。 |
| `continue`、`c` | ブレークポイント、選択肢、物語の終わりのどれかまで進めます（ウィンドウでは、プレイヤーがそのままプレイを続けます）。 |
| `next`、`n` | このシーン内の次のステップへ進みます。呼び出したシーンのステップは飛ばします。 |
| `step`、`s` | 次のステップへ進みます。呼び出したシーンの中にも入ります。 |
| `out` | 現在のシーンから戻った後のステップまで進めます。 |
| `pause` | 実行中のゲームを停止します。 |
| `vars [<frame>]` | 指定したフレーム（`0` が最も内側）の引数、ローカル変数、物語変数と、現在のステップの記録。 |
| `break <step \| file:line>...` | ブレークポイントを追加します。引数なしの `break` で一覧を表示します。 |
| `delete` | ブレークポイントをすべて削除します。 |
| `swap` | デバッグプロファイルで再ビルドし、新しいゲームに[ホットスワップ](#hot-swap)したうえで、新しいソースにブレークポイントを設定し直します。 |
| `help`、`quit` | |

選択肢を進めるにはアームを選ぶ必要がある（`push` を使います）ため、`continue`、`next`、`step`、`out` は選択肢で停止します。物語が終わりに達する場合は、最後のステップで停止してそのことを知らせます。

## `nav` {#nav}

`nav` は、現在の状態（シーン、その引数とローカル変数、物語変数）に一致するノードから物語グラフを探索し、指定したステップのいずれかの状態に至る最短経路を一つ探します。探索は現在のシーンの終わりを越えて、実際のコールスタックをさかのぼりながら進みます。答えは次のどれかです。

| 答え | 意味 |
| ---- | ---- |
| reachable | 最短経路上の選択肢の表。選択肢のステップ（`After Step`）、選ぶアーム（`Choose`）、そのテキスト（`Display`）を並べます。続けて、それらのアームを選ぶ `push` の引数と、経路上で行われる乱数の抽選を表示します。 |
| unreachable | 到達する方法はありません。物語グラフが完全な場合にだけ、こう答えます。 |
| unknown | グラフが不完全（`W5006` の上限か、打ち切った `W5007` の経路を示します）か、現在の状態がグラフにありません（デバッグ用成果物が古い、または上限を超えた先の状態）。 |

**乱数の抽選。** グラフは `rng_choose` が返しうるすべての値をたどりますが、実際のプレイはシードで結果が決まります。経路に抽選が含まれる場合、`nav` は現在の位置までと経路を、別のシードで再生してみます。最初に現在のシード、次に `0`、`1`、`2`、… と、最大 `--seeds` 回（既定は 1000）試します。ステップに届くシードが見つかればそれを提案し（`seed <n>` の後に `push`）、上限までに見つからなければそう伝えます。試すたびにそれまでの物語全体を再生するので、物語が長い場合や抽選が起こりにくい場合は時間がかかります。`nav` は確率（何個のシードに一つが経路どおりの値を引くか）も表示します。シードを変えると現在の位置より前の抽選結果も変わるため、それまでに選んだ選択肢が合わなくなって失敗することもあります。

アームのテキストは、経路をたどる再生から取ります（抽選がある場合は、見つかったシードで再生します）。どのシードでも抽選が経路どおりにならず、再生が届かなかった選択肢には `?` を表示します。

```text
(kagari) nav crate::AmusementPark#5
reachable: 9 steps
  |# |After Step             |Choose               |Display |
  |1 |crate::Start#2         |crate::Pick::Bold    |Be bold |
  |2 |crate::AmusementPark#1 |crate::Ride::Coaster |Coaster |
  push crate::Pick::Bold crate::Ride::Coaster
  draws: crate::AmusementPark draws crate::Coin::Tails (one of 2)
  the current seed already gives a path there: `push` it
```

## ブレークポイントとステップ実行 {#breakpoints}

**ステップブレークポイント**は、物語がそのステップに入ったときに停止します（`break crate::Start#4` のように指定するか、`s!(…)` や `choice!{…}` などステップを作る構文のあるソース行に設定します）。ステップを作る構文のない行に設定すると、**命令ブレークポイント**になります。こちらは、シーン、`pushdown fn`、`const fn`（レンダーを含む）の中で、その行のコードを実行する直前に停止します。`fn` の中の行はデバッグの対象外（システムのコード）で、コードのない行には設定できません。

コードの途中で停止しているときは、`stack` と `vars` でフレームとその変数を確認でき、`next`、`step`、`out` でコードを 1 行ずつ進められます。物語が次のステップに着くと、そのステップで停止します。物語を動かすコマンドは、物語が再びステップに戻るまで待ってから実行します。ウィンドウの場合、物語がコードの途中で停止している間はウィンドウを再描画しません。

デバッガー自身による移動（`goto`、`pop`、`seed`、`ls`、`detail`、`nav`）は、物語のコードを途中で止めずに再生します。`push` と実行系のコマンドは、命令ブレークポイントで停止します。

## ウィンドウで動くゲームのデバッグ {#window}

デバッグ用の通信路を開いてランタイムを起動し、そこに接続します。

```text
kagari-desktop-runtime target/v0 --debug-port 4711
kagari debug --attach 4711
```

デバッガーが物語を止めている間は、プレイヤーによる物語の操作（送り、選択肢、オート、スキップ）を受け付けません。メニュー、セーブ、バックログは使えます。ロードやニューゲームを行うと停止は解除されます。`continue` で物語の操作をプレイヤーに戻すと、ブレークポイントに達したときか `pause` を要求したときに、ゲームは再び停止します。移動するたびに、途中のアニメーションを省いて新しい状態をすぐに表示します。現在のステップ自体のアニメーションは、もう一度再生します。

## ホットスワップ {#hot-swap}

ホットスワップとは、物語の途中にいたまま、実行中のゲームを再ビルドしたゲームに差し替える機能です。シーンを編集して `swap` を実行する（または `--watch` に任せる）と、ゲームをデバッグプロファイルで再ビルドし、ランタイムが新旧二つのデバッグビルドを比べて変更のあったコードを見つけます。ホットスワップはデバッグ用の補助機能です。新旧どちらのゲームもデバッグビルドである必要があり、デバッガーなしで動かすゲームには一切負担をかけません。

コードが変わったシーンは**スタックから外します**。シーンの本体（ステップのテキストも含む）が変わった場合や、シーン内で実行されるコード、つまりシーンが使う `pushdown fn`、`const fn`、レンダーが変わった場合に、そのシーンは変更ありとみなします。開始シーンからコールスタックをたどり、最初に見つかった変更ありのシーンと、その上にあるシーンをすべて外します。そのうえで、外した一番下のシーンを呼び出し元から同じ引数で**呼び直します**。呼び直したシーンは新しいコードで最初のステップから始まります。呼び出し元の位置とローカル変数はそのままです。物語変数、`&mut` 引数の参照先の値、乱数の状態、位置、画面は呼び出した時点の状態に戻るので、外したシーンが行った処理はなかったことになります。新しいステップがすぐに表示され、物語はそこで停止します。

```text
(kagari) swap
wrote target/v0/game.kagari
swapped; called `crate::story::Greet` again (thrown off: crate::story::Greet), now at crate::story::Greet#0
stopped (swap) at crate::story::Greet#0
```

スタック上のシーンに変更がなければ、物語は今のステップにとどまります（`nothing on the stack changed`）。変更のあったシーンは、次に呼ばれたときに新しいコードで動きます。次の場合は、物語を開始シーンから同じ引数とシードで**やり直し**、その理由を表示します。

- 開始シーンそのものが変わった。
- 物語変数が追加・削除された、または型が変わった。
- 外さずに残る物語が持っている値を引き継げない。値の型が定義し直された場合や、値が指すアセット、`Setting`、`Meta` がなくなった場合です。
- 呼び直すシーンが、ゲームが呼び出しを記録し始める前に始まっていた。ウィンドウでは、デバッグビルドを `--debug-port` か `--debug-stdio` 付きで実行すると、起動時から記録します。クエリエンジンは常に記録しています。
- 新しいコードがすぐにエラーで止まった。

物語のやり直しもできない場合（開始シーンがなくなった、または引数が合わなくなった場合）は、ゲームの開始ページに戻ります。ゲームの上に開いていたメニューはスワップ時に閉じ、アセットは再ビルドしたアーカイブから読み直します。スワップ後の位置は通常の位置と変わりません。その後に作ったセーブは、新しいゲーム上で再生することでロードできます。

## エディタ {#editors}

`kagari dap` はデバッグアダプターで、標準入出力で Debug Adapter Protocol をやり取りします。Zed 拡張機能は、これをアダプター `Kagari` として登録します（[Zed](./editors.md#debugging-in-zed) を参照）。launch 設定ではゲームを起動し、既定ではウィンドウで起動します。

| キー | 意味 |
| ---- | ---- |
| `request` | `launch` または `attach`。 |
| `manifestPath`、`cwd`、`target` | プロジェクトとターゲット（`kagari debug` と同じ）。 |
| `mode` | `window`（既定）または `headless`（クエリエンジン）。 |
| `runtime`、`runtimeArgs` | ウィンドウで launch するときに起動するランタイムと、追加の引数。 |
| `entry`、`seed` | クエリエンジンの開始シーンとシード。 |
| `buildFirst` | 起動前にデバッグプロファイルでビルドします。既定は `true`。 |
| `stopOnEntry` | ウィンドウ用。物語が最初に入ったステップで停止します。 |
| `host`、`port` | attach 用。ゲームが待ち受けている場所（`--debug-port`）。 |
| `watch` | プロジェクトのファイルを監視し、変更があれば `kagari debug --watch` と同じように[ホットスワップ](#hot-swap)します。既定は `false`。 |

エディタの各表示は、物語に次のように対応します。スレッドは一つ（物語）で、コールスタックにはシーンが並び、変数欄には各フレームの変数と物語変数が出ます。ブレークポイントは行に設定し、続行、ステップオーバー、ステップイン、ステップアウトは上で説明したとおりに動きます。デバッグコンソールでは、このページのコマンド（`ls`、`nav crate::Start#9`、`push B`、`swap`）を実行できます。物語を操作するコマンドは、構造化された結果を返すカスタムリクエスト `kagari/stack`、`kagari/ls`、`kagari/goto`、`kagari/push`、`kagari/pop`、`kagari/detail`、`kagari/nav`、`kagari/seed`、`kagari/scenario` としても使えます。カスタムリクエスト `kagari/swap` は、ゲームを再ビルドしてホットスワップし、行のブレークポイントを設定し直します。応答には、結果（`kept`、`recalled`、`restarted`、`reset` のいずれか）、呼び直したシーン、理由、外したシーン、新しい位置が含まれます。条件付きブレークポイント、関数ブレークポイント、例外ブレークポイントには対応していません。ウィンドウで起動したゲームのログ（標準エラー出力）は、`stderr` の出力としてデバッグコンソールに送ります。
