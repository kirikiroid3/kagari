---
title: "デバッガー"
---

物語デバッガーは、物語を手でプレイせずに物語の中を移動し、物語についての問いに答えます。物語がいまどこにあるか、次に何が来るか、あるステップにここからまだ到達できるか、どの選択肢（と乱数の抽選）でそこに到達するか、です。デバッガーは、ウィンドウなしでゲームを実行する**クエリエンジン**上でも、**ウィンドウで実行中**のゲーム上でも動作します。ウィンドウでは移動のたびに新しい状態がすぐに表示されます。エディタはどちらにも Debug Adapter Protocol で接続します。設計については Develop Guide の [The Debugger](https://github.com/kirikiroid3/kagari/blob/main/docs/dev/src/runtime/debugger.md) を参照してください。

## デバッグビルド {#debug-builds}

デバッガーは、`kagari build --profile debug` が `game.kagari` の隣に書き出すデバッグ用成果物 `game.kagari-cache` を読みます（[ビルドプロファイル](./cli.md#build-profiles)を参照してください）。`nav` が必要とする探索された物語のグラフと、ローカル変数の名前です。これがなくてもほかのコマンドは動作し、変数は `arg0`、`arg1`、… と名付けられます。別のビルドのデバッグ用成果物は無視されます。`kagari debug` と `kagari dap` は、ゲームを起動する前に自分でデバッグプロファイルのビルドを行います。

## 位置 {#positions}

位置は**ステップ ID** です（`crate::story::Start#3`。関数のパス、`#`、関数内でのステップの番号です。[ステップ ID](../concepts/steps.md#step-ids) を参照してください）。選択肢の**アーム**は、セーブが記録するのと同じアーム ID で示します。アームの値のバリアントパス（`crate::Pick::B`）、または `#` とアームの並びでのインデックスです。デバッガーは、表示されているアームの 1 つを指すなら、アーム ID の末尾のセグメントも受け付けます（`B`、`Pick::B`）。

デバッガーは、セーブを読み込むのと同じ方法で物語を動かします。エントリーシーンから選択肢を再生します（[セーブ・リプレイ・決定性](../concepts/saves.md)）。その間は何も保存されず、何も聞こえません。既読フラグも、メタの書き込みも、オートセーブも、音声もありません。移動の後、物語は到達した場所で**停止**します。`continue` で先へ進みます。

## `kagari debug` {#kagari-debug}

```text
kagari debug [--manifest-path <PATH>] [--target <TARGET>] [--entry <PATH>] [--seed <N>] [--no-build]
kagari debug --window [--runtime <PATH>] [--manifest-path <PATH>] [--target <TARGET>] [--no-build]
kagari debug --attach <ADDRESS> [--manifest-path <PATH>] [--target <TARGET>]
```

`kagari debug` はプロジェクトをデバッグプロファイルでビルドし、ゲームを起動して、1 行に 1 つずつコマンドを読みます。既定ではクエリエンジンを実行します。物語は、物語のグラフが最初に挙げるエントリーシーン（または `--entry`）から、グラフにあるその引数とシード `--seed`（既定は `1`）で始まり、最初のステップで停止します。

| オプション | 意味 |
| ---------- | ---- |
| `--manifest-path <PATH>` | プロジェクトの `kagari.toml`。既定では最も近いもの。 |
| `--target <TARGET>` | デバッグするターゲット。既定では `build.targets` の最初のもの。 |
| `--entry <PATH>` | クエリエンジンが開始するエントリーシーン（クエリエンジンのみ）。 |
| `--seed <N>` | クエリエンジンの乱数シード。既定は `1`。 |
| `--window` | 代わりにゲームをウィンドウで起動します（`kagari-desktop-runtime`。`kagari` の隣か `PATH` から探します）。 |
| `--runtime <PATH>` | `--window` が起動するランタイム。 |
| `--attach <ADDRESS>` | `--debug-port` 付きで起動したゲームに接続します。`PORT` または `HOST:PORT`。何もビルドしません。 |
| `--no-build` | 先にビルドせず、ターゲットディレクトリにすでにあるファイルを使います。 |

場所は `file:line:column` で表示され、ファイルはプロジェクトのルートファイルのディレクトリからの相対パスです。コマンドはパイプで渡せます（`kagari debug < commands.txt`）。デバッガーは順に答え、入力の終わりで終了します。

## コマンド {#commands}

| コマンド | 効果 |
| -------- | ---- |
| `stack` | エントリーシーンから現在のステップまでのコールスタック。内側が先です。各シーンを、その引数と、いるステップ（または呼び出し位置）とともに示します。 |
| `ls [-h N \| --head N] [-t N \| --tail N]` | 現在のステップから次の選択肢までのすべてのステップを 1 行ずつ。ステップ ID、話者、最初の数語です。`-h` は最初の `N` 個、`-t` は最後の `N` 個を残します。 |
| `goto <step>` | 直前の選択肢から次の選択肢まで（両端を含む）のステップへ移動します。それ以外はエラーで、その 2 つの選択肢を示します。 |
| `push <arm>...` | 次の選択肢から始めて、最初のアームを選び、その次の選択肢へ進んで 2 番目を選び、と続けます。最後のアームを選んだ直後で停止します。アームを提示しない選択肢があれば push はそこで止まり、提示されているアームを挙げたエラーになります。 |
| `pop` | 直前の選択肢の、アームを選ぶ前に戻ります。`pop` のたびに 1 つ前の選択肢へ戻ります。 |
| `detail [<step>]` | ステップについてのすべて（既定では現在のステップ。それ以外は直前の選択肢と次の選択肢の間にある必要があります）。話者、ルビと効果付きのテキスト、ボイス、レンダーとそれがキーフレームかどうか。選択肢では、その `id` と、すべてのアームのアーム ID、テキスト、表示されるかどうかです。 |
| `nav <step> [--seeds N]` | 現在の状態からそのステップに到達できるか、どうやって到達するか（後述）。 |
| `seed [<n>]` | 乱数シードを表示するか、現在の位置をシード `n` で再生します（選択肢が合わなくなるとエラー）。 |
| `continue`、`c` | 先へ進みます。ブレークポイント、選択肢、物語の終わりまで（ウィンドウではプレイヤーがプレイを続けます）。 |
| `next`、`n` | このシーンの次のステップへ。呼び出したシーンのステップは飛ばします。 |
| `step`、`s` | 次のステップへ。呼び出したシーンの中にも入ります。 |
| `out` | 現在のシーンが戻った後のステップへ。 |
| `pause` | 実行中のゲームを停止します。 |
| `vars [<frame>]` | フレーム（`0` が最も内側）の引数、ローカル変数、物語変数と、現在のステップのレコード。 |
| `break <step \| file:line>...` | ブレークポイントを追加します。`break` だけなら一覧を表示します。 |
| `delete` | すべてのブレークポイントを削除します。 |
| `help`、`quit` | |

選択肢にはアームが必要なので（`push` を使います）、`continue`、`next`、`step`、`out` は選択肢で停止します。物語が終わるときは、最後のステップで停止してそのことを伝えます。

## `nav` {#nav}

`nav` は、現在の状態（シーン、その引数、ローカル変数、物語変数）に一致するノードから物語のグラフを探索し、実際のコールスタックをさかのぼって現在のシーンの終わりも越え、そのステップのいずれかの状態への最短の道を 1 つ探します。答えは次のとおりです。

| 答え | 意味 |
| ---- | ---- |
| reachable | 最短経路を実現する `push` の引数と、経路が通る乱数の抽選。 |
| unreachable | 道は存在しません。物語のグラフが完全なときにだけ主張します。 |
| unknown | グラフが不完全（`W5006` の上限、または諦めた `W5007` の経路を示します）か、現在の状態がグラフにありません（古いデバッグ用成果物、または上限を超えた状態）。 |

**乱数の抽選。** グラフは `rng_choose` のすべての値をたどりますが、プレイはシードに従います。経路が抽選を通るとき、`nav` は現在の位置と経路をほかのシードで再生します。現在のシードを最初に、次に `0`、`1`、`2`、… と、最大 `--seeds` 回（既定は 1000）試します。ステップに到達するシードを提案する（`seed <n>`、続いて `push`）か、上限内に見つからなかったことを伝えます。試行のたびにそれまでの物語全体を再生するので、長い物語や起こりにくい抽選では探索に時間がかかります。`nav` は確率（何個のシードに 1 つが経路の値を引くか）を報告します。別のシードは現在の位置より前の抽選も変えるので、それまでに行った選択肢が合わなくなってシードが失敗することもあります。

```text
(kagari) nav crate::AmusementPark#5
reachable: 9 steps
  push crate::Pick::Bold crate::Ride::Coaster
  draws: crate::AmusementPark draws crate::Coin::Tails (one of 2)
  the current seed already gives a path there: `push` it
```

## ブレークポイントとステップ実行 {#breakpoints}

**ステップブレークポイント**は、物語がステップに入ったときに停止します（`break crate::Start#4`、または `s!(…)` や `choice!{…}` などのステップのフォームがあるソース行）。ステップのフォームのないソース行は**命令ブレークポイント**です。シーン、`pushdown fn`、`const fn`（レンダーを含む）の中で、その行のコードが実行される前に停止します。`fn` の行はデバッグされず（システムのコード）、コードのない行は拒否されます。

コードの中で停止したときは、`stack` と `vars` がフレームとその変数を示し、`next`、`step`、`out` がコードを 1 行ずつ進めます。物語が次のステップに到達すると、そのステップで停止します。物語を動かす物語コマンドは、物語が再びステップにいるようになるまで待ちます。ウィンドウでは、物語がコードの中で停止している間、ウィンドウは再描画されません。

デバッガー自身の移動（`goto`、`pop`、`seed`、`ls`、`detail`、`nav`）は物語のコードを停止せずに再生します。`push` と実行コマンドは命令ブレークポイントで停止します。

## ウィンドウのゲームのデバッグ {#window}

デバッグ用の通信路付きでランタイムを起動し、それに接続します。

```text
kagari-desktop-runtime target/v0 --debug-port 4711
kagari debug --attach 4711
```

デバッガーが物語を停止している間、プレイヤーの物語の入力（送り、選択肢、オート、スキップ）は無視されます。メニュー、セーブ、バックログは引き続き動作し、ロードやニューゲームで停止は終わります。`continue` は物語をプレイヤーに返し、ゲームはブレークポイントで、または `pause` が要求されたときに再び停止します。移動のたびに、間のアニメーションなしで新しい状態がすぐに表示されます。現在のステップ自身のアニメーションはもう一度再生されます。

## エディタ {#editors}

`kagari dap` はデバッグアダプターで、標準入出力で Debug Adapter Protocol を話します。Zed 拡張機能はこれをアダプター `Kagari` として登録します（[Zed](./editors.md#debugging-in-zed) を参照してください）。launch の設定はゲームを起動し、既定ではウィンドウで起動します。

| キー | 意味 |
| ---- | ---- |
| `request` | `launch` または `attach`。 |
| `manifestPath`、`cwd`、`target` | プロジェクトとターゲット（`kagari debug` と同じ）。 |
| `mode` | `window`（既定）または `headless`（クエリエンジン）。 |
| `runtime`、`runtimeArgs` | ウィンドウの launch が起動するランタイムと、追加の引数。 |
| `entry`、`seed` | クエリエンジンのエントリーシーンとシード。 |
| `buildFirst` | 先にデバッグプロファイルでビルドします。既定は `true`。 |
| `stopOnEntry` | ウィンドウ: 物語が最初に入ったステップで停止します。 |
| `host`、`port` | attach: ゲームが待ち受ける場所（`--debug-port`）。 |

エディタの表示は物語に対応します。1 つのスレッド（物語）、シーンのコールスタック、各フレームの変数と物語変数、行のブレークポイント、そして上で述べた continue、ステップオーバー、ステップイン、ステップアウトです。デバッグコンソールはこのページのコマンド（`ls`、`nav crate::Start#9`、`push B`）を評価します。物語コマンドは、構造化された結果を返すカスタムリクエスト `kagari/stack`、`kagari/ls`、`kagari/goto`、`kagari/push`、`kagari/pop`、`kagari/detail`、`kagari/nav`、`kagari/seed` としても使えます。
